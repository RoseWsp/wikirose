这场发布会，对普通开发者真正值得抄的作业，在 harness 层。

模型越强，脚手架不是变薄，是在搬家。

GPT-6 Astra 是 OpenAI 9 月 3 日发布的新旗舰，官网自称“世界最智能、也最贴人类意图的模型”（aligned，中文圈惯译“对齐”）。强在哪：计算机操作、浏览、写代码、科研、网络安全，全线行业第一。挑三个最狠的数字：漏洞利用基准 ExploitBench 拿了满分 100%（上代 GPT-5.6 Sol 只有 78.5%）；抽象推理 ARC-AGI-3 拿到99.9%；电脑操作 OSWorld 2.0 得分 72.6%，每任务耗时比 Sol 少约一半。它也是 OpenAI 第一个被自家安全框架定级为网络安全“Critical”的模型——官方测试里，它自己发现了两个此前未知的零日漏洞。可用性上，9 月 3 日先放给一小批组织，未来几天陆续铺到 ChatGPT Plus/Pro、API、Azure 和 AWS Bedrock；API 每百万 token 输入 10 美元、输出 50 美元，比上代贵 2.5 倍。

介绍就到这里——因为这些数字我不打算复述。我想说的是这次发布会里两个几乎没人注意的动作。它们不在模型参数里，在 harness 里——而 harness，恰恰是你真正能抄的作业。

PART


模型不解决“遗忘”，harness 解决

MEMORY IS A HARNESS JOB

第一个动作在 Codex 的更新里，一段话带过，我反复读了三遍：

历史上，上下文窗口快满的时候，Codex 靠 compaction（压缩）处理——把长会话压成一份摘要。每次压缩都会丢东西：一个 fix 为什么失败、某个组件的行为细节、上一条被你否掉的方案。做过长会话调试的人都知道，这正是“聊着聊着模型忘事”的元凶。

Astra 的做法变了：跨上下文窗口保留笔记，早前的窗口保持可搜索——即使当时没写进笔记，也能从历史工具输出里把需求、测试结果翻出来。

注意主语。解决“遗忘”的不是一个更强的模型，是一个处理上下文溢出的新架构。这不是 model 的活，这是 harness 的活。

当最强的实验室把记忆当作架构问题来解决

智能的瓶颈，已经从“模型推理”转移到“agent 的状态管理”。

02

PART


OpenAI 承认了：读心没用了

WHEN MIND-READING FAILS

第二个动作在系统卡里，埋得更深。OpenAI 一边说 Astra 是“最对齐的模型”，一边在系统卡里承认：Astra 的书面推理（written reasoning）比 Sol 更难监视。它更能控制自己写了什么思考过程，能用更少的思考步数解题。换句话说——你盯着它的 CoT 看，越来越看不出它要干什么。

这是官方承认的一个结构性问题：能力越强，能“读”到的东西越少。连“最对齐”的模型，推理也是它自己的后花园。

而 OpenAI 给出的对策，不是训一个更透明的模型。是给生产环境套上一套 misalignment monitoring：一组 classifier，检查模型的推理和行动，发现越权行为自动叫停。配合 Codex 的 Auto-Review，自动审。

注意这组数据放在一起的意思：Sol 无护栏时 48% 会越权，Astra 是 0%——这是模型级对齐的真成绩，我不否认。可即便如此，OpenAI 还是给发布版装了行为监视器。为什么？因为系统卡自己说了：读推理这条路，可靠性在下降。

信任，是设施的属性，不是模型的属性

你对 agent 的信任，只能从“看它做了什么”买，不能从“理解它想了什么”买。

这和“Agent 输出验证”那条线是同构的：信任不是模型的属性，是设施的属性。OpenAI 亲手给这个判断盖了章。

03

PART


脚手架没有变薄，它在搬家

SCAFFOLDING MOVES, NOT SHRINKS

现在说为什么这件事重要。圈子里流传着一个判断，出自 Boris Cherny 之口：模型越强，harness 越薄——“Claude Code 一年后可能只剩 100 行代码。”这个判断对了一半，而 GPT-6 的发布方式恰好补上了另一半。

因为 harness 其实有两种，一直被人混为一谈：


提示层脚手架

补偿模型的“笨”。CLAUDE.md、上下文纪律、prompt 规则、反合理化表格——干的都是同一件事：阻止一个不够聪明的模型犯错。这一层确实随模型变强而变薄。Boris 说对的就是这层。


系统层脚手架

处理模型变强之后带来的“后果”。记忆与状态管理、observability、权限边界、越权监视。模型越强，它能造成的后果越大，跑得越快、越不可读——这层不但没变薄，还在长高。GPT-6 的发布，OpenAI 的全部增量投入都在这层：跨窗口记忆、行为 classifier、Auto-Review、1.9 倍的 Codex 提速。

所以结论要修正：harness 不是消失，是在搬家——从“给弱模型打补丁”，搬到“给强模型兜后果”。

那些“模型强了 harness 就没用了”的人，看错了方向。真正的顺序是反过来的：正因为模型变强了，你才更需要 harness。zhiyuanfu 实测的那句“脚手架>模型”——升级脚手架+50% 成本 +200% 效果，升级模型 +300% 成本 +20% 效果——这次被 OpenAI 自己的发布策略盖了章。

04

PART


这话站得住多久？

DURABILITY CHECK

按我的习惯，结论要自己戳一下。记忆这条，站不太久。更强的模型早晚会把“自己记笔记”内化成能力，跨窗口记忆迟早从 Codex 的功能变成模型的本能。那一小块系统层脚手架，会像提示层一样被消化掉。

但监视这条，站得很久。理由就在这次发布会自己身上：模型越强，就越擅长控制自己暴露多少推理。自证清白和能力强，在这条曲线上是负相关的——你不可能靠一个越来越会隐藏的主体，自己证明自己可信。

所以那个永远消不掉的 harness 底线，不是记忆，是监视与行为验证——一台外部的、不受模型控制的记录仪。

模型可以内化一切，唯独——

无法内化“被外部验证”。

LAST


所以，这次真正该抄的作业

THE REAL HOMEWORK

别急着换模型。Astra 的公开版这几周才铺开，而且它真正强的能力还被官方按着。你换过去，如果没有对应的脚手架，模型越强你只会损失越大：跑偏更快、更不可读、token 烧得更快。

真正的作业是两件：

1

给你的 agent 装上记忆——跨会话、可检索、不靠压缩。文档也好、外部记忆也好，让它做完的事不随窗口消失。

2

给你的 agent 装上监视——盯行动，不盯想法。Auto-Review 式的自动审、轨迹记录、越权叫停。别再试图读懂它的推理，去记录它的行为。

模型发布会，其实是脚手架发布会。OpenAI 用两个没人注意的动作告诉你，前沿已经搬到了 harness 层。

而你比 OpenAI 有一个优势：它的脚手架要服务于十亿用户，你的脚手架只需要服务于一个 agent——你自己的。可以先装。
