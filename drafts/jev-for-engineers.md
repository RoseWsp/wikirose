# Jev 快 200 倍，不是因为模型更强

> 是因为问题被重新表述了一遍。而 48 小时后社区抄走的那一半，恰好指出了没被抄走的那一半在哪。

---

9 月 15 日，TypeSafe AI 发布 Jev，自报比主流大模型快 **193.6 倍**、便宜 **444.6 倍**。定价：输入 $0.042/百万 token，**输出免费**。延迟 70–500ms。

先把这个数字拆开。快 200 倍不可能来自模型本身——它没有更大的模型，也没有更快的 kernel。它来自于一个更朴素的地方：**它不生成 token。**

Jev 的输出是三个原语之一，都带置信度：

| 原语 | 输出 |
|---|---|
| **Choice** | 从最多 **255** 个预设选项里选一个，返回概率分布 |
| **Score** | 在指定数值区间里打分 |
| **Noul** | 校准过的布尔概率 |

255 不是随手取的——`uint8`。**动作空间就是一个字节。**

## 机制：生成如何退化成分类

只要候选集是有限的、已知的，**"生成"就退化成"分类"，而分类可以并行**。这是那 200 倍的全部来源。

复刻者把这五步写得很清楚：

```python
# 1. schema 定义成一组带类型的字段（enum / boolean，候选集已知）
# 2. 对 context + schema 做一次 prefill，拿到 KV Cache
# 3. 把 KV Cache 沿 batch 维广播成每个字段一行
kv = mx.repeat(kv, M, axis=0)        # M = 字段数
# 4. 所有字段在一次 batched forward pass 里并行评估
logits = model(kv)                     # 切片 → softmax
# 5. JSON 由程序组装，不是生成出来的
```

自回归在第三步之后就不存在了。没有逐 token 采样，没有 beam search，没有 stopping criteria。**模型一次前向，把所有字段同时算完。**

顺带一个常被误读的实测：M4 Max 上，复刻引擎 4 字段从 420ms 降到 75ms，28 字段从 1.9s 降到 270ms。**注意加速来源不是模型更强，是跳过了生成 + 跨多个问题复用同一份 KV Cache。**这是推理工程优化，不是什么新范式。官方演示里 Jev 实时打 DOOM，每秒约 10 次决策、约 $7/小时——放在这个机制里完全说得通。

第五步值得单独记住：**JSON 是组装出来的，不是生成出来的，所以永远不可能格式错误。**

官方宣称的 **"0% 幻觉"**，指的是这件事。它是**构造性保证，不是实测数据**——保证输出在结构上跑不出 schema，**不保证判断内容正确**。一个格式完全正确的错误答案仍然是错的。

## 代价：枚举清单是有人手工写的本体论

可靠性是用"取消开放式即兴"换来的。

**模型只能在你已经枚举过的动作里选。它无法发现你忘了列进去的那个动作。**

对挂机跑 Minecraft，这不是问题。对"Agent 在 UI 里发现一条你没设计过的路径"，这是致命的。这条约束的工程含义比看上去重：**动作空间的边界，就是整个系统的能力边界**，而这条边界是人在写 schema 的时候画下的。

这也是为什么它吃不上"让模型自己想办法"那类收益。你没法给它更多思考预算来变强——**你只能给它更好的世界描述。**

## 定价结构暴露了架构

输入 $0.042/百万 token，输出免费。为什么？

因为一次决策只有几个 token，而世界描述很长。

> **思考免费，因为根本没有思考；账单是"看一眼世界"的钱。**

这个定价结构里藏着整个架构：**负担从模型搬到了环境编码和动作枚举上。**想让 Jev 变强，工程活全在你这一侧——状态怎么编码、动作怎么枚举、循环怎么搭。

Almeida 有句话在这个背景下才读得通：

> 我们有瓶中之闪电，却毫无用处……问题是我们一直在优化人类语言，**但计算机说另一种语言**。

## 真正没被解释的，是训练那一层

接口是工程，训练是断言。TypeSafe 没发论文、没放权重、没说参数量、没公开架构，**RLCD 的 reward function 未公开**。

他们的赌注在目标函数上。Almeida 是 RLHF 论文的共同作者，他现在的判词是 **"RLHF 是一条弯路"**：

> RLHF 优化的是"人类评分者更喜欢"，不是"更准确"。所以**过度承诺是被设计出来的特性**……无论模型错得多离谱，它们看起来都会是对的。

| 方法 | 优化对象 | 致命问题 |
|---|---|---|
| **RLHF** | 人类偏好 | 不可测的**代理指标**；奖励自信 |
| **RLVR** | 可验证的正确性 | 可测，但只在能验证的领域存在（数学、代码） |
| **RLCD** | **校准**：置信度与实际频率对齐 | 新，未经独立验证 |

校准解决的是一个非常具体的工程问题：**模型不确定的时候也输出自信的文字，程序读不出它的把握程度，于是必须有人在回路——自动化就卡在这里。**

校准过的概率才让软件能写这种分支：

```python
if p > 0.9:     auto_execute()
elif p > 0.6:   escalate_to_bigger_model()
else:           ask_human()
```

这三条分支是"把判断嵌进软件"的最小充分条件。缺了校准，每一条都得人肉当裁判。

**但校准和正确性是正交的**——这是这条技术路线最容易吹过头的地方：

> 一个永远回答"50%，我不确定"的模型是**完美校准的，而且毫无用处**。

校准只保证"你说的把握是真的"，不保证"你有把握的事是对的"。它拿到的是一份关于自身不确定性的诚实描述：**它知道自己云哪里是薄的，但那不等于云是对的。**

## 48 小时复刻压力测试：抄走了哪一半

发布后 48 小时内，社区冒出一批开源复刻。最早那个是 Hacker News 上的 `harshatheg/Qwen-2.5-1B-RLCD`，作者留了一句话：

> 你们 stealth 开发两年，我 stealth 开发两小时。

随后至少有 6 个命名各异的项目出现，72 小时内出现 wire-API 兼容版（TypeSafe 的 SDK 不改一行就能接上）。至少一个项目补加了商标免责声明。

**关键事实：没有一个复刻了 Jev 的模型或训练方法。它们复刻的全是接口。**

两条路线都走得通：

| 路线 | 做法 |
|---|---|
| **读 logits（无训练）** | 冻结的开源模型，候选映射到单个 token，一次前向读 logits → softmax |
| **为决策而训练** | 专门微调 + 事后温度缩放做置信度门控 |

第一条路线占绝大多数——**完全没走训练那段过程，拿个现成模型就能跑。**

分界线在这里变得非常干净：

```python
p = softmax(logits)   # ← 所有"读 logits"路线都拿这个当"置信度"
```

**softmax 给的是相对排序，不是校准概率。**模型说 0.9，不代表 90% 会对——只代表"这个选项比其他选项更像"。

有人总结得比谁都准：

> reading logits is **a ranking with a gap**, not calibrated confidence.

排序可以喂给 `argmax`，喂不了上面那三条分支。**这是接口层和校准层的差，也是被抄走的那半和没被抄走的那半的差。**

## 那个确实不舒服的问题

`TheoLeeCJ/openjev` 在 102 行 TypeSafe 子集上的自测：

| 模型 | modal agreement |
|---|---|
| 已发布 Jev | **0.883** |
| Qwen3.5 4B 复刻 | **0.845** |
| 浏览器内小模型 | 40.7 – 63.7% |

**一个 4B 的开源复刻，和已发布 Jev 差不到 4 个百分点。**

那么问题很直接：如果 84.5% 一致率的开源版对大多数用例就够了，Jev 剩下的价值是什么？

答案是**校准**——它押的不是准确率，是诚实。**复刻者抄走的是准确率，不是诚实。**

但这个问题没有任何一方能靠喊话解决，只能等付费数据。顺带把该打的折扣一起打了：所有数字自报，对照基线是竞品预测平均值，公司自认 193.6x/444.6x 是"接近现实收益上限"的高端值；没有具名客户，没有收入披露；第三方独立测试稀少。**信号很强，证据很弱。**

采用速度倒是真的：Vercel AI Gateway 上，24 小时内约 **13%** 的付费团队接入。Hugging Face 的 Niels Rogge 一句吐槽被到处引用——**"一个 JSON 分类器竟然有 1200 万次浏览。"**

## 那两年花在哪了

复刻潮最有意思的地方，不是打脸，是它把一个厂商声明干净地拆成了两层：**能被两小时复刻的，和不能被复刻的。**

两年和两小时差的不是写代码。**差的是走路。**

接口、格式、采样方式——这些都是**形态**，形态是可以传递的信息，所以可抄。而校准那一层，是 RLCD 那段训练过程在权重上压出来的**痕迹**。

这里有个容易被跳过的推论。Jev 内部**没有过程**：一次前向传播出结果，没有序列、没有展开、没有时间。它不属于"缺少体验的 AI"——**它内部没有过程**。

那过程去哪了？**被搬出去了。**搬到那份动作枚举清单、那份状态编码、那个外部循环上。而这些**都是有人走过过程之后留下的东西**：

> 写这份 schema 的人，经历过"在这个场景里哪些动作真的重要、哪些没用、遇到哪种情况该往哪走"。他走过的路，最后凝固成了那份清单。

**组件是痕迹的固态。**过程是流体的，走过去之后留下来的是形状——那份清单就是形状。

这条链推到末端只剩一句话：**枚举清单的长度，等于有人替这个模型走过了多长的过程。**你没走过的地方，它就没有选项。前面那条"无法发现你忘了列进去的动作"的约束，说的其实是这件事。

## 带走什么

给工程师的几条：

1. **"快 200 倍"买不到你的场景里。**它的前提是候选集有限且已知。你的问题如果不是这个形状，这套东西一点都不快。
2. **想清楚你要的是准确率还是校准。**这两件事正交，而且只有后者能写进控制流。如果你的下游是 `if p > 0.9`，那 `softmax` 给你的东西是骗你的。
3. **成本从模型侧搬到了你这一侧。**输出免费不是让你省钱，是把环境编码和动作枚举的活全留给了你。这笔账要提前算。
4. **看一个"新范式"声明，先看复刻潮复刻到了哪一层。**被两小时复刻的那层不是它的赌注；没人碰的那层才是。反过来，"被两小时复刻了"也不构成反驳——它只说明这家公司押的不是壳。

至于那批人的两年值不值、这条路线走不走得通，以后会有人算。

**但对走路的人来说，能不能被算出来，本来就不是这件事的意义。**

意义在里面，不在外面。
