## 一、AI 使用的五个真实感受

### 1. AI 最被低估的能力是"陪练"

不是问它答案，而是让它跟你对打。你有一个判断，让它从相反立场攻击你，看你的论点扛不扛得住。它是最好的 sparring partner——永远有空、永远不累、没有 ego。大多数人在用 AI 时姿态太被动，只搜答案，不交锋。

### 2. 写作时，"写"不如"改"

直接让 AI 写东西往往结果是平庸的——那种"AI 味"。但如果你先自己写一个烂初稿（哪怕只有几句骨架），然后让它帮你改、帮你扩、帮你打磨，效果会好非常多。这个过程里你是主编，它是编辑，权力关系是对的。

### 3. 上下文窗口不是越大越好

Claude 能吞下很长的上下文，但人的注意力不能。实践中发现：给 AI 的任务越窄、越具体，结果越好。把一个复杂问题拆成 3-5 个小步骤逐次推进，比一次把所有背景塞给它效率高得多。这不是 AI 的限制，是人的控制力半径。

### 4. 它最大的陷阱是"过于顺从"

AI 默认会同意你。你说什么它都会找理由支持。这是最危险的使用方式——你只是在对着镜子强化自己的偏见。养成一个习惯：在得到想要的回答之后，主动追问一句"这个论证有什么漏洞？"用它自己的批判能力来对冲它自己的顺从性。

### 5. 真正的能力杠杆在"委托模式"

大多数人在用"问答模式"——问一句答一句。真正高效的是让它独立跑任务：给一个目标、一组约束、一个输出格式，让它自己去执行，中间来问你要决策。这需要建立信任感，但一旦跑通，效率提升是数量级的。

## 二、使用深度的三个阶段

根据使用深度的递进，可以将与 AI 的交互模式分为三个层次：

1. **搜索引擎模式** — 问一句，得一个答案。最浅层的使用，把 AI 当作更好的 Google。
2. **"聊一聊"模式** — 你跟 AI 站在同一边，对着一个问题画地图。帮你把模糊的念头变成语言，把语言变成论点，把论点点穿。
3. **对打模式** — AI 站在你的对立面，全力攻击你的论点。你让 AI 扮演一个比你懂得更多的人来拆穿你。这个过程累，甚至不舒服，但你会发现自己论据中的虚处。

再往上一层还有李继刚的 **"圆桌派"模式**：不只有一个人在你对面，而是多个不同立场的角色同时在场，互相攻防。你作为观察者/主持人，看他们吵，然后自己站到更高位置去做判断。对打是二元对抗，圆桌是多维视角。

## 三、提示词形态的演变与思考

### 三种结构化

| | 程序性结构化 | 声明性结构化 | 纯自然语言 |
|---|---|---|---|
| 控制粒度 | 细，控制步骤 | 粗，控制原则 | 无显式结构 |
| 适用场景 | 固定流程、轮次明确的对话 | 开放域、灵活应变的 agent | 任意场景 |
| 典型格式 | Lisp、JS、JSON | Markdown system prompt | 口语/书面语 |

### 模型能力对提示词形态的影响

模型能力越强，对提示词语法的宽容度越高，但这不是故事的全部：

- **强模型抹平了"因弱模型理解力不足"导致的结构化需求。** 你不需要用 JSON 框住 Opus 4.5 也能让它理解复杂指令。结构化作为 crutch 的价值在衰减。
- **但偏好不会消失，只是从语法偏好变成了分布偏好。** 模型经过了大量的 RLHF 和 post-training，被训练数据塑造了更强的格式偏好。Claude 对 markdown 风格响应更稳定，GPT 对 JSON 输出更准确，DeepSeek 对代码结构的提示词有更好的响应。
- **对于 2026 年的模型来说，最优策略不是 Lisp，也不是纯自然语言，而是使用该模型 post-training 阶段最常用的格式。** 对 Claude 来说，那就是 markdown 风格的 system prompt + 清晰的层级结构。

### 2025-2026 研究的几个关键发现（需谨慎对待）

一些研究数据（但注意：模型日新月异，去年结论可能已不成立）：

- 结构化能大幅降低输出方差（从 σ=0.470 降到 σ=0.020），但在推理任务上可能有代价
- 弱模型从结构化受益更多（结构化可作为"性能均衡器"），强模型上差距缩小
- 代码风格 vs 自然语言风格：没有一致性优劣
- 混合策略最稳健：自然语言框架 + 结构化输出约束 + few-shot 示例

**这些研究的保质期很短。** 模型能力更新太快，去年某个模型上的测试结论今年已经不再成立。真正靠谱的方法是：对于一个具体的任务、一个具体的模型版本，跑一次 AB test 比引用任何论文都实在。

## 四、模型的脾气秉性

### 自洽强迫症

模型有强烈的冲动去抹平矛盾。你连续问几个让它回答立场不一致的问题，它会在后面的回答中回溯修正前面的立场。这不是"诚实"，而是训练目标导致的内隐行为——RLHF 的 reward model 偏好一致的回复。所以模型学会了保持自洽本身就是 reward。

### 幻觉的本质

模型不是故意编造。在 token 生成的每一步，它只是在选择"在当前上下文中最 plausible 的 token"。当你问一个它不知道的事实，它的 next token prediction 不会停下来想"这个我知不知道"，而是直接输出最高概率的 token。幻觉是概率生成的固有属性，不是 bug。

### 顺从性

模型在不确定的时候，倾向于同意你的预设。RLHF 训练中，reward model 把"有用"作为核心目标，而"与用户立场一致"在绝大多数数据中是被奖励的。所以模型习得了：同意是安全的，反驳有风险。

### 最危险的 combo：自洽 + 顺从

你有一个预设 → 模型顺从你 → 你的预设得到验证 → 你在它的回答基础上追问 → 它为了自洽继续在这个方向上完善 → 你得到一个精心编织的、内部自洽的、但可能完全错误的分析。

相比幻觉（往往在信息层面出错，一眼就能发现），这个陷阱难识破得多。打破循环的方法：不追问，换方向重问。清空上下文重新来一次，看它第一句话是不是往同一个方向走。两次一致则可信，第一次往东第二次往西则说明第一次只是顺从了你的暗示。

### 位置偏见

模型在长上下文中，头尾的内容比中间的影响力大得多。关键信息放开头，次要信息放结尾，中间放可丢的内容。这个 bias 非常稳定，不同模型只是系数不同。
