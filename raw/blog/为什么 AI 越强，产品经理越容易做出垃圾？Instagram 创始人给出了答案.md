# 为什么 AI 越强，产品经理越容易做出垃圾？Instagram 创始人给出了答案

最近看了一期播客访谈，嘉宾是 Mike Krieger，Instagram 的联合创始人，现在在 Anthropic Labs 负责产品。主持人是 Every 的 Dan Shipper。两个人聊了将近一个小时，话题围绕着一个核心问题展开：在 AI 时代，做产品这件事到底发生了什么变化？

这期对话信息密度很高，几乎每隔几分钟就会蹦出一个让人停下来想一想的观点。我试着把里面最有价值的部分梳理出来。

## 搭建变简单了，但做出好产品并没有

Mike 做了一个很有意思的思想实验。他回忆了 Instagram 的诞生过程：他们先花了将近一年时间做一个叫 Bourbon 的产品，发现不行，然后用三个月时间做出了 Instagram。他问自己，如果放到今天，哪些环节会变得无关紧要？

答案是：搭建本身。他让 Claude 重新搭建了 Bourbon，两个小时就搞定了，功能齐全，甚至还自动加上了滤镜功能，因为模型知道 Instagram 后来加了这个。

但他紧接着说了一句很关键的话：AI 模型很擅长往产品里加功能，但它不擅长判断该砍掉什么。

这个洞察非常深刻。做产品最难的部分从来都不是把功能堆上去，而是知道什么该留、什么该砍。这种判断力来自于长时间跟真实用户打交道的过程中一点一点积累起来的直觉。AI 可以帮你在几个小时内从零搭到完整产品，但它在这个过程中替你做了大量决策，而这些决策背后的直觉，你并没有真正建立起来。

这一点对任何使用 AI 工具的人都值得警惕。工具越强大，越容易让人跳过那些看似低效但实际上非常重要的思考过程。效率提升了，但判断力可能在悄悄退化。

## 室内树的比喻：快速生长未必是好事

Dan 在对话中提了一个特别精彩的比喻：如果你在室内种一棵树，没有风吹，它会长得很快，但树干不够强壮，容易歪斜。因为树需要风的阻力才能长得结实。

Mike 非常认同这个说法。他分享了自己在 Anthropic Labs 的亲身经历：因为 AI 让搭建变得太容易了，他们在一个项目的 V1 阶段就严重过度开发。每个功能看起来都只是一个小 PR 的工作量，用 Claude Code 很快就能搞定，于是不断往上加。结果做出来一个功能矩阵，测试起来极其复杂，连向用户解释都困难。

他还引用了另一个比喻：这就像你直接被扔进一部电视剧的大结局，完全不认识里面的角色，也没有前面几集的铺垫，根本不知道发生了什么。

这个现象在我们日常工作中也很常见。当做一件事的成本变得很低的时候，人的本能反应是尽可能多做。但多并不等于好。很多时候，克制和取舍才是真正考验功力的地方。AI 让执行变得廉价了，但这反而让判断力变得更加稀缺和珍贵。

## 重写不再可怕：软件开发的心理模型变了

以前在软件行业有一条铁律：不要轻易重写代码。因为重写意味着你要把 V1 里积累的所有隐性知识重新来过，风险极高，周期极长。经典的例子就是网景浏览器的重写，直接把公司拖垮了。

但 Mike 说，这条规则在 AI 时代需要重新审视了。现在重写一个系统可能只需要几天，模型还能帮你对比新旧版本，确保没有遗漏。他们在 Labs 内部已经多次经历这样的过程：搭建完整产品，发现过度复杂或者核心假设有误，推倒重来做 V2，然后在 V2 的基础上继续迭代。

这种心态的转变很有意思。以前重写是一件让人心痛的事情，因为意味着之前几个月甚至一年的工作白费了。但现在，重写可能只是上周的事情，这周就能重新来过，而且还能趁机砍掉很多不必要的东西。

这个思路其实可以延伸到很多领域。我们经常因为沉没成本而不愿意推翻已有的方案，觉得之前投入的时间和精力不能浪费。但如果重新来过的成本大幅降低了，那坚持一个有问题的方案反而才是真正的浪费。

## Agent Native：2026 年软件设计的核心原则

对话中反复出现的一个概念叫 Agent Native，翻译过来就是原生支持 AI 代理的产品设计理念。

简单来说，就是你的产品里用户能做的事情，AI 代理也应该能做。产品要足够灵活和可扩展，让 AI 能够以设计者没有预想到的方式来使用它。

Mike 用 Claude Code 举例：它就是一个典型的 Agent Native 产品。它是一个代理，能在你的电脑上做你能做的任何事情，而且可以自定义、可扩展，容易上手但能做出各种意想不到的事情。

他还提到了一个很有趣的细节。他看到有人在用 Claude 的时候，创建了一个文档，然后对 Claude 说：帮我把这个加到项目知识库里。结果 Claude 回复说：好的，让我告诉你怎么手动添加。Mike 觉得这就是典型的没有做到 Agent Native，这个操作应该是 Claude 自己就能完成的。

他把 Claude AI 称为 2024 年的产品，Claude Code 称为 2025 年的产品，两者在 Agent Native 的程度上有明显差距。这意味着产品设计的标准在快速演进，今天看起来还不错的产品，几个月后可能就显得笨拙了。

## 测试 Agent Native 产品：一个全新的挑战

传统软件可以写端到端的功能测试来验证。但 Agent Native 的产品因为本身就强调灵活性和不可预测性，传统测试方法就不太管用了。

Mike 分享了一个特别有画面感的故事。他在开发一个 Agent Native 的 iOS 应用原型时，让 Claude 来测试这个应用。结果 Claude 在应用的聊天功能里跟自己聊了起来。一个 Claude 扮演用户说：我今天工作压力好大，老板对我很凶。另一个 Claude 回复说：哦，真的很抱歉听到这个。两个 AI 就这么一来一回地聊了起来。

这种场景你根本不可能提前写一个单元测试来覆盖。所以 Mike 认为，测试 Agent Native 产品需要搭建专门的测试框架，让系统尽可能多地被真实使用，因为你永远不知道 AI 会把你的应用带到什么状态。

他总结说：让底层架构足够健壮，能够承受你没有预料到的使用方式，同时又保持足够的灵活性。这就是 2026 年软件设计的艺术和科学。

## 团队怎么搭：联合创始人模式

Mike 分享了 Anthropic Labs 内部的团队组织方式，非常有启发性。

他们采用的是一种类似孵化器的模式。每个项目的核心是一个有极强信念感的人，这个人可以是设计师，也可以是有产品思维的工程师，但很少是纯粹的产品经理。这个人必须有那种撞墙也要把事情做成的劲头。

Mike 说，他们复盘那些被关停的项目时，发现一个共同点：团队里没有人真正觉得这个东西非做不可。大家都觉得“好像还行”，但没有人为之燃烧。这就是项目的死亡信号。

围绕这个核心人物，他们会配备互补的技能。因为 Labs 采用孵化器模式，每两周评估一次项目，决定是加倍投入还是释放人员回到资源池，所以团队成员可以灵活流动。

Dan 也分享了 Every 的做法：每个产品只有一个人负责全栈，从设计到工程到营销全部自己来。这个人以前必须是技术背景很强的创始人类型，但现在要求变了，只要能熟练使用 Claude 或 Codex 这类工具，加上出色的产品感觉和审美就够了。

两种模式的共同点很明显：在 AI 时代，一个人能 hold 住的范围变大了，但团队过早扩张反而会拖慢速度。Mike 特别提到，他们发现在想法还能装进一个人脑子里的阶段，加人实际上是负效果，因为大量时间会被花在协调和对齐上。

这对很多创业者和团队管理者来说是一个反直觉的提醒。我们习惯性地觉得人多力量大，但在快速迭代的环境里，小团队的敏捷性可能远比人数更重要。

## 企业客户与快速迭代的矛盾

Mike 坦诚地谈到了一个现实困境：AI 产品需要快速迭代，但企业客户需要稳定性。

他讲了一个亲身经历。他们做了一次 Claude AI 的大改版，团队很自豪地发布了，结果收到一封愤怒的邮件：一个企业客户刚录制了 20 小时的培训内容来教员工使用旧版本，现在全部要重做。

从那以后，他们学会了在企业端更温和地推进变更，同时保持核心产品的快速演进。他的策略是：让企业客户理解这列火车会一直往前开，但沿途会提供必要的控制开关。

他还提到了一个更深层的观点：在以前的技术周期里，产品迭代是以年为单位的。但现在，三个月前的产品可能就已经过时了。创业公司如果为了迎合大企业客户的需求而固守旧版本，很可能会被从零开始重新思考这个问题的新公司取代。

这个矛盾没有完美的解决方案，但 Mike 的态度很明确：宁可主动淘汰自己的旧版本，也不要等着被别人淘汰。

## 个人 AI 代理：2026 年最重要的产品问题

对话最后聊到了 OpenClaw 和个人 AI 代理的话题。Mike 认为这是 2026 年上半年最重要的产品问题：在完全开放（AI 可以做任何事情）和严格受控（每个操作都需要权限）之间，到底存在什么样的产品形态？

Dan 分享了一个很有意思的观察。他说当你有了自己的 AI 代理，给它起了名字，跟它长期互动之后，会产生一种很强的归属感。Claude 很好用，但感觉是公共的。而你自己的代理，它了解你的习惯、你的偏好、你的工作方式，它感觉是属于你的。

Mike 回应说，他在 Claude Code 里已经设置了一个强指令：尽量不要自己干活，把任务委派给子代理。这样做的好处是主循环始终保持可用状态，你随时可以跟它对话。这让它感觉更像一个你在交谈的伙伴，而不是一个你派出去干活、偶尔卡住五分钟的工具。

Dan 还提到了一个很酷的现象：在他们公司里，每个人都有自己的 AI 代理，而这些代理会逐渐变得跟主人一样专业。别人信任你，就会信任你的代理，于是形成了一个影子组织架构，每个人的 AI 代理都因为主人的专长而被其他人使用。

这个趋势指向一个很有想象力的未来：你的 AI 代理可能会成为你专业能力的延伸和放大器。你在某个领域越专业，你的代理就越强，别人就越愿意使用它。某种意义上，培养你的 AI 代理就是在培养你自己的竞争力。

## 贯穿始终的一个信号

回头看这整期对话，有一条线索贯穿始终：AI 让执行变得极其廉价，但这恰恰让那些不能被自动化的东西变得更加珍贵。产品直觉、取舍判断、对用户的深度理解、在不确定性中做决策的勇气，这些能力不会因为 AI 变强而贬值，反而会因为周围一切都在加速而变得更加稀缺。

Mike 作为一个亲手打造过十亿级用户产品的人，现在又站在 AI 产品的最前沿，他的判断很清醒：工具变了，速度变了，但做出真正好产品的底层逻辑没有变。你还是需要跟真实世界碰撞，还是需要在过程中建立直觉，还是需要有勇气砍掉那些看起来不错但其实不必要的东西。

只不过现在，这一切发生的速度快了十倍。
