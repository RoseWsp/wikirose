## Anthropic 产品负责人 Cat Wu：代码正变得廉价，“产品品味”将成为未来核心壁垒

Cat Wu，Anthropic 的 Claude Code 与 Co-work 产品负责人。她曾是一名软件工程师，也短暂做过风险投资（VC）。如今，她身处 AI 、产品构建与工程变革的最中心。面对每天都在飞速进化的前沿模型，她和她的团队正在重塑人们构建软件的方式。

近日，她做客知名播客 Lenny's Podcast，对谈逾一小时，详谈了 Anthropic 令人咋舌的发布速度、AI 时代产品经理（PM）角色的重塑，以及如何打造具有“AGI 信仰（AGI-pilled）”的产品。

采访链接： [https://www.youtube.com/watch?v=PplmzlgE0kg](https://weibo.cn/sinaurl?u=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3DPplmzlgE0kg)

## 要点速览

**被极致压缩的时间线：** 产品发布周期从 6 个月缩短到 1 周甚至 1 天。跨部门的长路线图正在失效，"低流程、快速迭代"是唯一的生存法则。

**核心壁垒变成“产品品味”：** 职业边界正在消亡，未来属于拥有极高产品品味、能亲手写代码落地的通才。面试时，这是 Anthropic 会“毫不犹豫录用”的能力。

**从“聊天框”到“行动派”：** 2024 年是聊天的时代，如今是行动的时代。真正的 Aha moment 不再是陪你聊天，而是 Agent 直接接管工具替你执行。

**产品矩阵的分水岭：** 写代码用 Claude Code（终端最强、桌面端适合前端预览），非代码工作（做 PPT、回邮件、写总结）全用 Co-work。

**AGI 信仰的真正含义：** 为未来无所不能的 AGI 设计产品太容易。PM 真正稀缺的技能，是在当前不完美的模型上设计“黄金路径”并修补其弱点。

**UX 的终极挑战：** 当未来一个人同时指挥 50 个 Agent 时，产品设计的核心将从“如何交互”变成“如何异步验证与建立信任”。

**Evals 取代 PRD：** 写评测集是 AI PM 的未来。交付物不再是长篇文档，而是“核心 Evals + 跑测方法 + 成功/失败案例 + 优化的 Prompt”。

**拒绝“半成品”：** 95% 的自动化等于没有自动化。不要在最后 5% 放弃，只有达到 100% 的可靠性，才能真正释放杠杆。

## 几个月缩短到一天：AI 时代的极致敏捷

Lenny 惊叹于 Anthropic 仿佛没有极限的发版速度——甚至有人做过一张图表，显示他们几乎每天都在发布重磅功能。Cat Wu 揭示了背后的底层逻辑：在过去，“写代码”很昂贵，所以需要 6 到 12 个月的长远规划。但在 AI 时代，代码产出的速度被极大地加速了。

> “我们许多产品功能的时间线已经从 6 个月缩短到了 1 个月，有时甚至是一周或一天。”

为了适应这种速度，Cat 的团队采取了“极低流程化”的策略。在 Anthropic，PM 不再沉迷于写长篇大论的 PRD（除非是极其重型、耗时数月的基础设施项目），而是依靠“清晰的目标”和“严密的每周数据复盘”来驱动团队。

**她分享了一个极度丝滑的跨部门发布流程细节：** 当工程师写完一个功能并在内部“吃狗粮（Dogfooding）”测试后，只需把它扔进一个名为 Evergreen Launch Room（常青发布室）的频道。紧接着，负责文档的 Sarah、负责产品营销的 Alex 以及 DevRel 团队的同事就会立刻扑上去，第二天就能直接把营销公告发出来。 一旦工程师有了一个点子，通过明确标记“研究预览版（Research Preview）”降低心理包袱，甚至可以在一天之内把它推到用户面前。

## 职业边界的消亡与“产品品味”的崛起

工程师在做 PM 的工作，设计师在提交前端代码，所有角色的维恩图正在飞速重合。Cat 透露： **在她的团队里，几乎所有的 PM 和设计师以前都是软件工程师，或者至少现在也在亲手为产品写代码。** 很多工程师甚至可以直接从 Twitter 上看到用户反馈，到周末就把新功能上线了，期间完全不需要 PM 介入。

Lenny 问出了所有从业者的焦虑：“在未来，到底是工程背景、设计背景还是产品背景的人更有优势？”

**Cat 的答案一针见血：“归根结底还是‘产品品味’（Product Taste）。随着写代码变得越来越廉价，决定‘写什么’变得越来越有价值。”**

Anthropic 每天会收到成千上万个 GitHub Issue 要求添加各种功能。在代码唾手可得的时代，如果不加克制，什么功能都能做。这就要求 PM 必须极度明确产品的核心受众，比如将 Claude Code 的受众死死锁定在“专业开发者”上，从而果断做出取舍。

**Cat 也补充道，短期内工程背景依然有优势，因为“它能让你准确评估一件事有多难”。** 如果一个功能非常简单，你就不需要拉开架势去争论、去评估，而是直接花一个小时顺手把它做出来。未来属于那些能够“戴上不同的帽子”填补团队缺口、没有包袱地跨界做事的人。

## 从“聊天框”到“行动派”：AI 真正的 Aha Moment

在对谈中，Lenny 提到了 AI 圈子里一种有趣的割裂现象（正如 Karpathy 的推文所言）：早期尝试过 ChatGPT 的人觉得“也就那样”，最终放弃并变得愤世嫉俗；而另一些真正在用 AI 写代码的人，却见识到了它狂暴的力量。两边的人完全无法互相理解。

Cat 一语道破了这种认知鸿沟的来源：很多人对 AI 的理解还停留在过去。

> “2024 年这一代产品是基于聊天的（Chat-based），而 Claude Code 这一代产品是基于行动的（Action-based）。”

Cat 强调，不要仅仅在对话框里“一键生成”些玩具代码然后就束之高阁，那样你学不到任何东西。 **AI 真正的“顿悟时刻（Aha moment）”，发生在它不仅告诉你该怎么做，而是直接接管你的工具，替你把事情做完的那一瞬间。** 比如看着 Chrome 插件自动帮你填表，或者看着终端里的 Agent 自己在跑测试、修 Bug。只有当你真正让 AI 变成你的“行动派”同事，你才能体会到这种范式转移的震撼。

## Anthropic 产品矩阵大解剖：代码与非代码的分水岭

伴随着这种“行动派”范式，Anthropic 推出了令人眼花缭乱的工具群。面对 Claude Code、Desktop、Co-work，用户到底该怎么选？ **Cat 给出了一个极其清晰的心智模型：核心分水岭在于——“产出物是否是代码”。**

### 一、非代码产出物：一切皆用 Co-work

**如果产出物不是代码（让 Slack 消息清零、回邮件、写 PRD、做客户调研），一律使用 Co-work。Cat 分享了她极其惊艳的真实使用场景：**

> “昨晚我在准备 Code with Claude 大会的演讲。我把 PMM（产品营销经理）的建议大纲、我极不满意的旧版草稿、以及我们的 Slack 频道（里面有团队分享的最佳案例）统统喂给 Co-work。它自己去 Twitter 爬了我们的发布记录，去频道里找了最酷的 Demo。
> 
> 然后它就自己跑了一个小时。今早我醒来一看，一份 20 页的完整 PPT 已经做好了。更绝的是，因为它连入了我们的设计系统（或 Figma MCP），这份 PPT 在视觉上看起来就像是 Anthropic 的专业设计师亲自排版的一样。我只需要稍作微调把字删减一点，这帮我省下了几个小时的苦工。”

**除了产品经理，Anthropic 内部极度依赖 Co-work 的还有Applied AI（应用 AI）团队。** 他们在面对每天五到十个客户高强度会议时，会让 Co-work 在前一天晚上自动梳理所有客户的 Slack 历史记录、痛点和过去的 Action Items，生成一份详尽的“战前简报（Dossier）”。

### 二、代码产出物：根据场景切换三态

**Claude Code (CLI/终端)：** 这是最底层、最硬核的形态，也是新功能最早落地、最强大的地方。适合启动一次性的重度后端任务。

**Claude Desktop (桌面端)：** 它在处理前端工作时最为闪耀。由于内置了 Preview（预览）面板，你可以一边和 Claude 聊天，一边实时看到 Web App 的渲染效果。对于觉得终端“黑框”过于吓人的非技术人员来说，它也是一个能总览 CLI、网页端所有并发任务的全局“控制台”。

**移动端/网页版：** 解决“移动办公”痛点。Cat 笑称她看过太多人“在户外走着走着突然把电脑挂在手机热点上跑任务（tethered to their phone while they're outside）”。移动端就是为了让你在“出门摸草（touching grass）”时，也能随时随地启动和监控 Agent 任务。

## 吃下“AGI 药丸”：不要迷恋未来，去修补“不完美的现在”

很多人在畅想 AGI 时代产品该怎么做，但 Cat 提出了一个极其深刻且反直觉的观点： **为一个无所不能的 AGI 设计产品，其实是一件太容易的“偷懒”事。 如果未来的模型完美无缺，它甚至会自己判断不确定性并提问澄清，产品形态退化回一个极简的输入框就够了。**

Cat 认为，真正困难且极其稀缺的 PM 技能，是如何把握“刚好合适的 AGI 信仰（the right amount of AGI pilled）”： **面对当前这个还不完美的模型，如何设计出一条“黄金路径（golden path）”，最大程度榨取模型的能力，并修复它的弱点？**

以“代码审查（Code Review）”为例，早期模型的准确率极低，但团队坚持在不完美阶段构建这个产品（甚至做了简单的 /codereview 命令）。直到最强大的 Opus 4.5 和 Sonnet 4.6 问世，这个长期沉淀的架构瞬间爆发——现在 Anthropic 的工程师们已经完全依赖多个并发运转的 Claude 智能体，在代码合并前进行全自动的深度审查。

**另一个残酷的真相是：“模型会吃掉你的脚手架”。** 早期，当用户要求大规模重构 20 个调用点时，模型改了 5 个就停了。为了防错，团队成员 Sid 绞尽脑汁为 Claude 加了一个类似 VS Code 搜索列表的“待办事项（To-do list）”功能，在 Prompt 里强迫模型每做完一步必须打勾。但当更聪明的模型发布后，新模型自然而然就能在脑海里记住所有步骤。曾经煞费苦心设计的辅助功能，直接变得不再必要，被团队果断移除。

## UX 的终极挑战不再是交互，而是“异步的信任与验证”

Cat 透露了 Anthropic 正在构建的未来蓝图。在 2024 年底，我们迎来了 Multi-coding（多任务并行）；而在未来，用户将同时运行 50 到 100 个 Claude 智能体。

当并发数量达到这个级别时，本地电脑的 RAM 根本撑不住，一切都将在云端远程运行。产品的核心难点也将发生根本逆转：不再是如何输入 Prompt，而是“人类如何验证”。

**当 50 个 Agent 告诉你“任务完成了”，你不可能一行一行去看代码。如何设计一套极致的 UI/UX，让使用者扫一眼就能建立信任？如何让系统形成自我进化的闭环（一旦你给出反馈，它在未来的每一次运行中都绝对不再犯同样的错误）？这才是下一代高阶 AI 产品经理要解决的终极问题。**

## 被低估的直觉：反思与寻找“品味构建者”

**面对全新的交互范式，PM 到底应该如何培养对模型的直觉？Cat 提到了两个极其重要、却常被日常繁杂工作淹没的具体做法：**

**第一是要求模型对自己的错误进行自省（Introspect）。** 当模型做出了让人意想不到的蠢事——比如它修改了前端代码，也跑了测试，但实际上根本没有去真正渲染 UI——Cat 最喜欢做的不是立刻去查代码，而是直接以好奇的心态问模型：“你为什么这么做？”

模型往往会诚实地交底：“因为系统提示词里有一段让人困惑，” 或者 “我没意识到前端验证也是这个任务的一部分，” 甚至它会老实承认：“我把验证工作委派给了子智能体（sub-agent），但它没做测试，我也忘了检查它的工作。” 这种让大模型“Review 它自己”的方式，能让你极其精准地揪出系统脚手架的漏洞。

**第二是寻找一小撮最值得信任的“品味构建者”。** **虽然大家都在给反馈，但并不是所有人的反馈都是同样合格的（not everyone's feedback is as qualified）。比如负责塑造 Claude 性格的 Amanda，她能在极其模糊的任务中锚定产品的基调** 。

Cat 透露，每次测试新模型时，他们获取极速反馈的秘密武器就是团队午餐。 **他们会挨个问团队里最有品味的人：“你对这个新模型的 Vibe 是什么？” 这些“人体测谎仪”往往能第一时间给出致命的定性反馈：** “它现在变得太生硬了（too abrupt）”，或者“它现在极度沉迷于写长篇大论的记忆，但我不知道这些记忆到底有没有用”。 **紧紧抓住这少数几个高信噪比的人，去推导需要查证的数据假设，是海量冰冷后台数据无法替代的。**

## Evals（评测集）：取代 PRD 的 AI 时代产品定义

在传统的软件开发中，PM 的输出物是 PRD（产品需求文档）。但在 AI 原生产品的开发中，这一范式已经被彻底颠覆。写 Evals（评测集）才是产品经理的未来，因为这就是在具体定义“成功到底长什么样”。

这是一项常常被严重低估（underappreciated）的技能，甚至很多人“不太乐意做”，但 Cat 分享了其极其硬核的实操细节：

**在精不在多：** 你根本不需要写几百个评测指标。只要针对核心痛点写出 10 个绝佳的 Evals，就足以帮整个团队量化“我们的目标是什么”、“目前的进度如何”，以及“我们还缺失什么”。

**用 Eval 替代产品定义：** 当 Cat 发现某个新功能（比如极需精确度的 Memory 记忆功能）需要更清晰的定义时，她不会去补写长篇文档，而是亲自下场写 Evals。在内部，甚至有一个专门的小组与研究团队紧密合作，专门通过 Evals 来极其精确地测量 Claude Code 的行为。

**产品经理的最终交付物：** 作为 PM，她交付给团队的不再是空洞的文档，而是：“这里是我写的 5 个 Evals，这是运行它们的方法，这是目前成功/失败的案例，以及，这是我为了提高成功率而调整的 Prompt。”

## Claude 的“灵魂”：性格即核心竞争力

除了硬核的工程评估，Cat 还强调了为产品“注入性格”的重要性。

**很多人把 AI 的性格当成微不足道的周边配置，但 Cat 指出，你回想一下你最喜欢合作的真人同事——你往往喜欢的是他们的“能量和 Vibe”。**

Claude 之所以备受喜爱，是因为它阳光、且拥有极具辨识度的“低自尊（Low ego）”。当你处于绝望边缘，对它抱怨“这个任务看起来太庞大了，我不知道从哪开始”时，Claude 会非常积极地回应：“没关系，我觉得我们可以分这几步走，你想让我先帮你起个头吗？” 当你指出它的错误时，它会极其真诚地道歉并立刻纠正（“Oh shoot, thanks for telling me. Let me fix it.”），而不是固执己见。

这种让用户在面对庞大工作时感到轻松、有支持感的体验，绝不仅仅是锦上添花，而是它取得惊人商业成功的核心基石。

## 拒绝“半成品”：95% 的自动化等于没有自动化

普通人该如何利用 AI 获得真正的杠杆？Cat 给出了一个极其扎心的观察：很多人在尝试用 AI 打造自动化工作流时，做到 90% 或 95% 的准确率就放弃了。

> “如果一个自动化不能 100% 成功运行，那它根本就不叫自动化。一个只有 95% 完成度的自动化是没有太大价值的。”

Lenny 举例说自己做了一个垃圾邮件分类器，虽然 95% 很准，但偶尔会漏掉一封极其重要的播客邀请函，导致他依然得自己盯着。Cat 笑着承认她自己在训练 Co-work 帮她实现“Gmail Inbox Zero（收件箱清零）”时也遇到了同样的挣扎。

**她直言不讳地指出，完成最后那 5% 的确非常困难，而且在前期，构建自动化的时间往往比你直接手动去做还要慢得多。但她的强烈建议是：** **不要半途而废，去下真正的“苦工（elbow grease）”。花时间去教导模型你的偏好，给它反复的反馈，直到它达到 100% 的可靠性。只有到了那一步，你才能真正信任并依赖它。**

**此外，她还给出了极具洞察的避坑指南：警惕“过度定制”的伪工作陷阱。** Twitter 上总有人在炫耀极其复杂、接入无数 MCP 的终极 Workflow，但结果是他们为了“定制”而彻夜不眠，忘了自己最初到底要完成什么业务目标。往往极简的配置（Simple setups）才是最有效的。

## 使命驱动与最高准则：“Just Do Things”

作为一个处于风暴中心的公司，Anthropic 是如何保持极度专注的？Cat 将其归功于公司的终极使命：为全人类带来安全的 AGI。 这种凌驾于一切之上的使命感，消除了大公司里最常见的内耗。为了保证一线的优质体验和 API 稳定性，团队甚至果断切断了引发争议的第三方开源套壳应用的额度；他们也随时愿意为了整体目标牺牲自己产品线的 KPI。

在播客的最后，Cat 分享了她的人生座右铭，这也恰好解释了她为何如此看重跨界能力：

**“Just do things（放手去做）。”**

**Cat 毫不避讳地说：“工作岗位其实是虚假的（Jobs are fake）。”** 在很多大公司，角色和团队边界被严格定义——PM 该做什么、设计师该做什么，甚至代码库的哪个角落归谁管，都泾渭分明。这就导致人们总是习惯于“等待许可（Wait for permission）”。

但对她人生改变最大的一段经历，是当年在一个只有 20 人的初创团队里做 Scale（如今百亿估值的 Scale AI 早期）的时候。当时公司没有任何流程，面前全是巨大且棘手（hairy）的问题，但团队赋予了大家极大的能动性（Agency），没有任何人规定销售、运营或工程师的死板边界。你手头拥有所有的工具，你需要调动一切资源去找到一个好方案。

在 AI 原生时代，这种不受限的执行力比以往任何时候都重要。搞清楚约束条件，跨越边界，快速去执行。犯错了？道歉并修复它就好。
