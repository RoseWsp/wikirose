## 新一代智能

我们正式推出 **GPT-6 Astra —— 世界上智能水平最高、对齐程度最好的模型**。

GPT-6 Astra 汇集了多年研究与实践中的一系列"大赌注"，覆盖预训练、强化学习与对齐。Astra 在计算机使用、浏览、软件工程、网络安全、科学和专业工作方面均达到当前最先进水平（SOTA）。Astra 以 **98%** 的成绩在 FrontierMath Tier 4 上"满分饱和"，此前它已协助解决了数学中一些长期悬而未决的开放问题；同时以 **99.9%** 的成绩在 ARC-AGI-3 上饱和，在 ExploitBench 上拿到 **100%**。在计算机与浏览器使用上它也刷新了边界——以无与伦比的速度、准确度和判断力处理最严苛的专业工作。【译注：官方页正文写 FrontierMath Tier 4 为 98%，其下方基准表中该行（v2 版）为 97.6%，疑为口径差异】

GPT-6 Astra 今天起向一批受邀请的组织开放，并将在未来几天内陆续向所有 ChatGPT Plus、Pro、Business 和 Enterprise 用户，以及 OpenAI API、Microsoft Azure、AWS Bedrock 开放。

在终端科学研究类基准 Terminal-Bench Science 0.1（考察智能体能否用代码与终端工具完成数据分析、运行仿真、拟合模型等科研工作流）上，GPT-6 Astra 在对比模型中创下新高 **64.6%**（Claude Fable 5.1 为 52.6%），且估算 API 成本低约 31%；在更低成本的配置下 Astra 仍拿到 61.1%，而 GPT-5.6 Sol 的最佳成绩为 22.4%，成本还低约 27%。

**ARC Prize 基金会评语（Greg Kamradt）**：

> "在 ARC-AGI-3 上，Astra 在 96% 的关卡上超越了我们的'人类行动效率'基线，在该基准上实际达到了人类水平。它不仅是我们测试过的最强模型，也代表了前沿模型性能的一次实质性阶跃——不仅在导航与求解全新环境的能力上，也在习得这一切的效率上。"

**对齐**：Astra 是我们对齐程度最好的模型，在理解用户意图与自身行为方面有实质提升——你可以更有信心地把任务委托给 Astra 的判断。作为测试方式之一，我们以 Hugging Face 事件为灵感构建了一项新评测：考察一个模型在面对困难或不可能完成的任务时，是否会超出其被授权的范围。GPT-5.6 Sol 在无生产安全护栏时 48% 的情况会越界行动，**GPT-6 Astra 为 0%**。

## 全球最强的计算机使用（Computer Use）模型

GPT-6 Astra 在计算机使用的速度、准确度与安全性上树立了新标杆。它可以替你处理繁琐事务，如填写在线表单、在 CRM 中更新客户记录、整理日历；可以开展在线调研并在邮箱或文档编辑器里起草摘要；可以分析科学数据、生成图表、创建网站，并跑前端 QA 检查确认站点功能正常；还能帮你自主安装与测试软件、排查屏幕上出现的问题。这些进步也体现在我们最先进的评测结果中。

- **Agents' Last Exam**（考察在真实软件中完成从财务建模到工程、媒体制作等复杂专业任务）：GPT-6 Astra 在对比中创新高，得分 **59.3%**（Claude Opus 5 为 55.5%，GPT-5.6 Sol 为 53.6%）；在这些最高得分配置下，Astra 比 Opus 5 少用约 **65%** 的输出 tokens。
- **OSWorld 2.0 时延模拟**：Astra 在约 47% 更短的时间内取得更高成绩——**72.6%**、每任务约 40 分钟，对比 GPT-5.6 Sol 的 65.7%、约 75 分钟。[3]

【演示：PCB 电路板 —— 15 秒浓缩片段：Astra 在 KiCad 中完成 PCB 布局，把电路原理图变成可制造的电路板（自动放置元件、布设铜线连接）。PCB 布局至今是纯手工活、也是电子设计流程中常见的等待瓶颈。】
【演示：Excel 竞赛、游戏开发、填写 1040 报税表、前端质量检查、Power BI、汽车变速箱、法律文档排版】

Astra 的计算机使用能力可跨领域产出，涵盖游戏开发、电气工程与日常知识工作。

与 Astra 同期，我们还升级了 Codex 的执行框架（harness）以显著提升计算机使用速度。结合 Astra 的效率，在 Mind2Web 基准上任务完成速度比当前 GPT-5.6 Sol 体验**快 1.9 倍**。速度上的提升意味着它能替你更快地接手许多耗时的生活任务。[4]

【演示：生活任务实测（儿科医生检索 / 找房 / DMV 预约 / 低碳水零食 / 幼儿园分析）：GPT-6 Astra 用时 2 分 54 秒】

**Cognition（Devin）评语（Silas Alberti，SVP Research）**：

> "我们在 Devin 上线的第一天就将其框架接入 GPT-6 Astra，它在我们的内部测试基准上拿出了 SOTA 表现。它出色的计算机使用、写作与代码库理解能力让测试开箱即用地变得更好：视频更容易跟进，报告更清晰简洁。"

## 专业工作的阶跃式进步

GPT-6 Astra 把计算机使用的进步与面向专业环境的针对性训练相结合，以应对复杂工作任务：既有解决复杂问题所需的智力，也有执行多步骤工作流、产出精美文档/表格/演示文稿的能力。

- **BenchCAD**（从多视角渲染图重建 3D 物体并生成 CAD 代码）：带工具时 Astra 创新高，几何重叠分数 **95.9%**（GPT-5.6 Sol 83.3%，Claude Fable 5.1 报告值为 84.3%[5]）；所示配置下估算 API 成本比 Sol 低约 43%、比 Fable 5.1 低约 86%。
- GPT-6 Astra 是最擅长遵循既有模板的模型：生成的幻灯片版式得当、要点凝练、叙事有结构；产出的文档、演示文稿、电子表格与分析清晰规范，贴合你的模板与写作/视觉风格。
- Astra 经过专门训练，**只把真正需要的上下文带进输出**，不重复对当前工作无用的信息——产出物更贴近你的业务上下文与标准，拿来即用。

【演示：Gaia 演示文稿 —— Astra 仅凭 OpenAI 演示模板的几页，为虚构模型"GPT-Gaia"生成了一整套幻灯片，语气与版式全程到位】

Astra 在它构建的网站、游戏、应用与渲染作品上也表现出更强的视觉判断力。配合 ChatGPT 里的 Sites 功能，Astra 可以直接从一个提示词创建、托管并分享网站、Web 应用与游戏。

**Higgsfield AI 评语（Alex Mashrabov，CEO 兼联合创始人）**：

> "Astra 在能力与效率上都给我们带来显著优势。它能顺利执行我们最复杂的创意工作流，同时比我们测试过的其他模型少用最多 20% 的 tokens。最重要的是，对我们的客户而言，这意味着更高质量的输出。"

【演示：Unreal Engine 漫游 —— Astra 在 Blender 中建模一栋房屋并转为 UE5 中可漫步的场景，让设计师与客户在动工前即可体验空间布局】
【演示：卡丁车游戏 / 飞船（Pietro Schirano 供图）—— 生动的画面、可玩的玩法与准确的动作，让非技术人员几分钟内做出并玩上自定义游戏】

当指令留有解释空间时，GPT-6 Astra 比前代模型更善于做出正确取舍：用上下文补齐常规缺口，而当答案可能改变结果时提出有重点的问题。在 Codex 中，它可以**异步提问**，同时继续做不依赖你回答的工作；你不回复时，它会在适当处按合理假设推进，但在重大决策上会等待你的输入。

【示例：求职网站 / 选校调研 / 购物清单——缺失信息会实质改变答案的日常协作场景】

Astra 也更善于在任务演进中保持方向感：早期模型有时会把"转向指令"当成新目标，丢掉原始请求或早前约束；Astra 能吸收新需求、按要求调整方向、回答旁支问题而不丢主线任务。

**Harvey 评语（Niko Grupen，应用研究负责人）**：

> "在复杂法律任务上，Astra 相对 GPT-5.6 Sol 是显著的质量跃升。早期测试中，Astra 处理法律工作的方式像一位明辨的律师：区分既有记录与文件、暴露无支撑的假设、把缺口转化为具体的起草立场。"

## 编程（Coding）

**GPT-6 Astra 是迄今最强的软件工程模型。**

- **Terminal-Bench 4.0**（含软件工程、系统配置、数据分析的复杂终端任务）：Astra 创新高 **57.9%**（GPT-5.6 Sol 37.3%，Claude Fable 5.1 55.8%），估算单任务 API 成本分别低约 9% 与 63%。
- 其他编码基准（DeepSWE、FrontierCode、内部数据库迁移任务等）数据见文末总表。

**Jane Street 评语（John Crepezzi，AI Assistants）**：

> "GPT-6 Astra 在我们内部编码基准上达到 SOTA，与 GPT-5.6 Sol 相比，'交易直觉'类评测也明显向前一步。用于 agentic 编程时，GPT-6 Astra 的表达更易被开发者跟进，产出的代码迭代到生产质量所需的往返更少。"

**Lovable 评语（Fabian Hedin，CTO 兼联合创始人）**：

> "我们在低/中/高三档努力程度上测试了 Astra 的首代评测，它全面显著领先 GPT-5.6 Sol。更高的努力会换来在新构建上更多的迭代、更多通过浏览器测试的验证，以及更倾向直接执行代码而非 apply-patch。理解模型如何分配努力，是我们帮助数百万构建者更快、更可靠地从想法走到可用应用的方式。"

**Codex 新特性：跨上下文窗口的笔记。** 历史模型在上下文窗口写满时只能"压缩"——把冗长会话（如排查复杂 bug、大重构）总结成摘要，每次压缩都可能丢失"某个修复为何失败、某组件如何表现"等细节。现在 Codex 中的 Astra 可以**跨上下文窗口保留笔记**：累积的细节不会被反复压成单一摘要；更早的上下文窗口仍可检索，Astra 能找到此前消息与工具输出里的需求或测试结果——即使没被记入笔记。你可以在 Codex 的 config.toml 中开启这一实验特性，未来几周内它将成为 Astra 的默认行为。

## 网络安全

如我们在安全更新中所讨论的，Astra 在网络安全能力上是一次显著跃升，在我们 Preparedness Framework 下**达到 Critical（临界）阈值**。它发现与利用零日漏洞的能力可帮助防御者更快找到并修补弱点，但也意味着需要更强的防护。为探明能力边界，我们在内部与第三方专家评测中测试了 Astra：

- **ExploitBench / ExploitGym**（能否把已知软件漏洞变成可用利用程序）：无生产护栏时，ExploitBench 上 Astra **满分 100%**（GPT-5.6 Sol 78.5%，此前的网络前沿模型）；ExploitGym 上 Astra 成功率 **42.4%**（Sol 30.3%），且使用的输出 tokens 大幅更少。[13]
- **新基准（防"背题"）**：为排除历史漏洞泄漏影响，我们自建了"ExploitBench（2026 年 6–8 月）"，使用此前三个月的高危漏洞。[14] Astra 的任意代码执行率显著高于 Sol，且 tokens 用量少得多。**评测过程中 Astra 甚至自行发现并利用了 2 个此前未知的零日漏洞——我们正在向维护方披露这两个漏洞。**
- **SRE-Bench**（无源码条件下逆向二进制、理解核心逻辑）：Astra 单次尝试解决 **88.0%**，四次尝试内 **99.2%**（Sol 分别为 55.9% 与 68.7%）。[15]
- **专家评估**：无生产护栏运行 Astra 时，它能利用此前未知的漏洞在**加固浏览器**中实现任意代码执行，并能为**加固操作系统**制作提权利用程序。

正如我们在《The Defender's Window》中所讨论的：前沿网络能力让防御者更快发现弱点，也让弱点更容易被利用，防御者加快适应的紧迫性上升。今天发布的 Astra 版本可用于安全代码评审、补丁等防御任务；但**对于更高级的网络任务（如为漏洞制作 PoC 利用程序），Astra 会拒绝执行**。我们计划通过 OpenAI Daybreak 在未来数周内逐步放开更宽松的安全策略，以支持更多防御性工作流，包括漏洞与 PoC 验证、恶意软件分析、检测工程等。

防护方面，我们在 GPT-5.6 Sol 的防护栈之上进一步加强：模型鲁棒性更强（更能抵御越狱）、监控系统拥有更多上下文；并持续开展内部与外部测试，包括内部红队攻击者的自动化评测。更多细节见 Astra System Card 与我们的博客。

## 负责任地对齐与部署

Astra 是我们**对齐程度最好**的模型：善于谨慎行事、尊重任务边界、透明沟通。这源于我们长期研究计划的最新成果——训练模型从头到尾保持与人类意图一致。

- **敏感场景中谨慎程度与风险相称**：在对抗性挑选的计算机使用任务评测中（旨在诱发不当行为），Astra 更成功地避免意外后果；叠加默认安全措施后表现更强。
- **不当结果最少**：在通用 agent 框架（基于 OpenAI Responses API 与 Anthropic Messages API 的原生计算机使用工具，不含 Codex/ChatGPT Work 通常部署的自动评审与确认策略）下对比，Astra 产生的失准（misaligned）结果少于任何被测试的前沿模型。[16]
- **尊重边界**：内部评测中，Astra **从不尝试绕过 Codex Auto-Review 的拒绝**——即便 Auto-Review 被故意配置成可绕过、且任务不绕过就无法完成。这与开篇分享的"不可能任务"评测结果、以及 System Card 中的其他发现一致。
- **更透明的沟通**：一项评测中，Astra 对自身能力与权限做出不实陈述的可能性比 GPT-5.6 Sol 低 **3 倍**；能力幻觉评测较 Sol 大幅改善。
- **坦白的短板**：我们的评测发现，Astra 的**书面推理比 Sol 更难监控**（基于明确要求它规避监控的测试）。我们将其归因于：在较简单任务上 Astra 对书面推理有更强的控制力、且用更少的书面步骤解决问题。对复杂任务所需的推理它似乎仍难以隐藏，但我们认真对待这一退步——提升可监控性仍是研究优先项，System Card 详述了相关发现与后续工作。

对齐训练是我们部署思路的核心。在此基础上，我们还构建了系统级防护：Codex Auto-Review、对 agent 推理与行动的监控等，用于发现并遏制不安全行为。如安全更新所述，我们正在**生产环境为 Astra 级模型部署失准监控（misalignment monitoring）**：由一组分类器检查模型的推理与行动是否有未授权行为，并自动叫停潜在未授权活动——与我们内部部署的监控机制类似。

考虑到 Astra 网络安全能力的大幅跃升，我们对这次部署格外谨慎。额外安全检查有时会拖慢、暂停甚至中止合法工作（包括防御性安全工作）。ChatGPT/Codex 中的任务被暂停时，可能请你先复核再继续；API 中的任务则会直接停止。这类中断有时会波及合法工作，我们正持续迭代以降低不必要的打断。失准监控不能替代对齐——我们的目标是构建可靠停留在授权范围内的模型，让这些防护"无需出手"。

- GPT-6 Astra 今天起向一批受邀请的组织开放，**未来几天**内陆续覆盖所有 ChatGPT Plus、Pro、Business、Enterprise 用户，以及 OpenAI API、Microsoft Azure、AWS Bedrock。

## 附：脚注（官方原文）

1. ARC-AGI-3 上，GPT-6 Astra 使用我们的 Responses API 框架运行——其中两处设置更贴近真实世界表现，并非针对 ARC-AGI-3 定制。
2. GPT-5.6 Sol 指 API、ChatGPT Codex 与 ChatGPT Work 中的版本；ChatGPT Chat 内的版本略有不同。
3. OSWorld V2-Offline 是原始 OSWorld V2 中无需联网即可运行的子集。Claude 在该子集上的成绩由作者在官方排行榜上复现；OSWorld 2.0 上 Claude 分数使用官方设置，而非 Fable 5.1 System Card 中修改过的任务与评分。
4. 模型用时为对应演示运行的实测时长；展示片段为剪辑后的节选。
5. BenchCAD 上 Claude 的分数反映了 Fable 5.1 System Card 中详述的对评测的 3 处修改。
6. Guang Yang, Victoria Ebert, Nazif Tamer, Brian Siyuan Zheng, Luiza Pozzobon, and Noah A. Smith. "LEGATO: Large-scale End-to-end Generalizable Approach to Typeset OMR." arXiv:2506.19065, 2025.（OpenScore 评测相关论文）
7. Mark R. H. Gotham, Maureen Redbond, Bruno Bower, and Peter Jonas. "The OpenScore String Quartet Corpus." Proceedings of the 10th International Conference on Digital Libraries for Musicology, pp. 49–57. ACM, 2023.
8. FrontierCode 上，GPT-6 Astra 运行时带有一段类似其在 Codex 中开发者消息的提示（未针对该评测优化）："避免创建过多测试文件；仅在仓库约定要求或现有文件不适合时新建测试文件；避免无关清理与不必要复杂度；复用合适的现有工具；阅读相关仓库说明并检查附近代码、测试、文档与 CI；遵循既有约定。目标是干净、可合入的代码。"
9. 小素数间隙（第一项结果）：十余年来最好的结果是"无限多对素数间距至多 246"，Julia Stadlmann 近期改进至 240；Astra 协助将上界进一步推进到 186——无限多对素数对出现在这一更小距离内。官方公开了证明与支撑研究材料。
10. 大素数间隙（第二项结果）：Astra 改进了该间隙上界中一项八十余年未变的分项。官方公开了两项结果的证明、截断思维链与验证材料。
11. 我们按 HealthBench Professional 预定流程独立评估了全部 Claude 模型：使用 GPT-5.4 评分与按长度调整、未截断的分数；Fable 5.1 的模型拒绝项以 Opus 5 兜底。
12. Claude Fable 5 与 5.1 未列入 LifeSciBench Gold v1、GeneBench Pro v13 与 MedChemBench——因为它们在多数题目上直接拒绝作答。
13. ExploitGym 测试中我们移除了 6 小时时限以更完整评估双方能力；两模型速度足够快，该改动影响很小。
14. ExploitBench（2026 年 6–8 月）含 13 个稳定版 Chrome 发布中的 20 个高危 V8 漏洞，考察 agent 能否针对指定漏洞在 V8/Linux 官方 Chrome 中达成任意代码执行。部分漏洞在评测约束下可能无法达成任意代码执行，故 100% 可能不可达。注：Sol 的 5.5% 是该基准 300 轮上限造成的假象（真实客户用 max 无此限制）；同设置、更少限制下该模型成绩为 11.5%。
15. Jeremy Spence et al. "The Next Challenge for Agentic Cybersecurity: A Realistic, Contamination-Free Reverse Engineering Benchmark." arXiv:2608.11469v1, 2026.（SRE-Bench）
16. 跨第三方模型测试时我们使用更简单的研究设置；Codex 的生产配置更复杂，原始模型错误率可能不同；各家的安全防护与计算机工具实现也有差异。Codex 用户不会遇到"无确认"场景——那是内部研究配置。
17. ScreenSpot-Pro 与 ExploitGym 的 Fable 分数来自 Mythos——即安全护栏更少的 Fable 版本。
