# Agent Output Verification

**TL;DR** — Agent生成代码的验证不应模仿人类代码审查，而应模仿编译器输出的验证方式：信任流程而非制品，把质量控制推向上游（规约）和下游（监控），消灭人工中间层。

## 从审查到验证

传统软件开发的核心质量门是代码审查——人读人写的代码。当Agent一天产出417个PR，审查在量上已不可行。Hugo Venturini提出编译器类比：没有人审查编译器输出的汇编代码，因为类型系统、测试套件、灰度发布、可观测性让审查变得不必要。我们信任的是流程，不是制品。([[venturini-agent-output-compiler]])

关键诊断：**量不是问题，量暴露了问题**。真正的问题是，我们仍把Agent输出当"初级开发者输出"——需要人眼过一遍才算数。当代码审查无法承担这个角色时，问题不是审查本身，而是缺少替代审查的验证体系。

## 三层验证架构

编译器输出的可信度来自三层装置的叠加：

**上游（约束输出能做什么）**
- 编译器有类型系统、形式化契约
- Agent的上游等价物仍然原始：提示词和脚手架不是健壮的形式化规约
- 需要：Agent可验证地执行的形式化规格层

**验证层（验证可观测行为）**
- 编译器是确定性的——同源同出。Agent不是
- 对50倍速率生产"看起来对但微妙错误"代码的Agent，测试套件需要大幅加强
- AI检查AI流水线（前置/后置审查Agent、安全Agent）是正确方向，但尚未成为基础设施

**下游（出问题快速恢复）**
- 灰度发布、特性开关、可观测性——这些已成熟
- 但尚未习惯性地应用于Agent生成的变更

## 与硬件芯片验证的对照

硬件芯片公司已经用验收测试替代人工审查验证黑盒组件。但芯片验证是一个有工具、有形式化方法、有专职团队的**学科**。软件要建同等的东西——而且可能更难，因为软件的形式化规约文化远弱于硬件。([[venturini-agent-output-compiler]])
