# Agent Output Verification

**TL;DR** — Agent生成代码的验证不应模仿人类代码审查，而应模仿编译器输出的验证方式：信任流程而非制品，把质量控制推向上游（规约）和下游（监控），消灭人工中间层。

## 从审查到验证

传统软件开发的核心质量门是代码审查——人读人写的代码。当Agent一天产出417个PR（Michael Novati在2026年2月的记录），审查在量上已不可行。Hugo Venturini提出编译器类比：没有人审查编译器输出的汇编代码，不是因为盲目信任——编译器出过臭名昭著的灾难性bug——而是构建了一整套让审查变得不必要的装置：类型系统约束输出能做什么，测试套件验证可观测行为，灰度发布和可观测性确保出问题快速回滚。我们信任的是**流程**，不是**制品**。([[venturini-agent-output-compiler]])

关键诊断：**量不是问题，量暴露了问题**。真正的问题是，我们仍把Agent输出当"初级开发者输出"——需要人眼过一遍才算数。当代码审查无法承担这个角色时，问题不是审查本身，而是缺少替代审查的验证体系。

## 三层验证架构

编译器输出的可信度来自三层装置的叠加：

**上游（约束输出能做什么）**
- 编译器有类型系统、形式化契约
- Agent的上游等价物仍然原始：提示词和脚手架不是健壮的形式化规约
- 需要：Agent可验证地执行的形式化规格层

**验证层（验证可观测行为）**
- 编译器是确定性的——同源同出。Agent不是
- 对50倍速率生产"看起来对但微妙错误"代码的Agent，测试套件需要大幅加强
- AI检查AI流水线（前置/后置审查Agent、安全Agent）是正确方向，但尚未成为基础设施

**下游（出问题快速恢复）**
- 灰度发布、特性开关、可观测性——这些已成熟
- 但尚未习惯性地应用于Agent生成的变更

## 与硬件芯片验证的对照

硬件芯片公司已经用验收测试替代人工审查验证黑盒组件。但芯片验证是一个有工具、有形式化方法、有专职团队的**学科**。软件要建同等的东西——而且可能更难，因为软件的形式化规约文化远弱于硬件。([[venturini-agent-output-compiler]])

## 官方盖章：读心让位于盯行为

"验证要看行为、不看思想"这条判断，第一次被发布方自己承认。GPT-6 Astra 的系统卡把**书面推理更难监控**列为官方短板：模型对书面推理的控制更强、用更少的书面步骤解题，能"读"到的东西反而更少 ([[gpt6-astra]])。

而对策不是造一个更透明的模型，是上系统层监视：OpenAI 为 Astra 部署了生产级 misalignment monitoring——一组 classifier 检查 Agent 的**推理与行动**，发现越界自动叫停；Codex 内置 Auto-Review，评测中 Astra 从不尝试绕过它（即使被故意配置成可绕过）。一个重要的 nuance：即便模型级对齐做到了"无护栏 48% 越界 → 0%"，官方仍给发布版装了行为监视器——因为官方承认读推理这条路可靠性在下降。([[gpt6-astra]])

这对验证体系意味着什么：**验证的对象正在从"模型想了什么"移向"模型做了什么"**。信任不是从理解内心买的，是从行为记录买的。而 OpenAI 同时声明"失准监控不能替代对齐"——行为监视是兜底，不是替代品。两层都要：先尽量训练出可靠停留在授权范围内的模型，再用监视接住剩下的尾巴。

## 不舒服的真相

抵抗灭灯代码库的工程师，如果穿越回编译器时代，可能也会反对不审查链接器输出——不是理性判断，是对信任迁移位置的不熟悉。编译器没有让我们停止关心正确性，它移动了正确性被强制执行的位置。灭灯代码库也一样：可怕的不是AI写代码，而是有多少团队没把"替代代码审查的东西"当成严肃工程来做。

这不是反对灭灯代码库的论据——我们正在被推向那里——而是对"负责任地到达那里"到底需要什么的诚实评估 ([[venturini-agent-output-compiler]])。

## 与wiki其他概念的关系

- [[harness-engineering]]：脚手架工程的上游约束是Agent输出验证的"上游层"——为Agent构建工作环境和约束条件
- [[self-healing-pipeline]]：自愈流水线的检测-分诊-修复-验证闭环是Agent输出验证的"下游层"
- [[agentic-engineering]]：工程纪律角度——在使用Agent加速的同时保持质量门槛
- [[agent-native-tooling]]：验证体系的工具本身也应该为Agent优化，而非为人类审查者优化——类型是描述"代码应该做什么"的信息密度最高的方式，不是护栏，而是信息
- [[builder-reviewer-model]]：Reviewer角色的核心能力从"读代码"转为"设计验证体系"
- [[ai-first-prerequisites]]：自动化测试和CI/CD是验证体系的底层前提
- [[compulsive-capability-use]]：验证体系是应对强迫性使用的工程手段——Agent对新能力的过度使用只有被验证体系捕获后才能被约束
- [[harness-engineering]]：Boris预言Claude Code一年后只剩100行代码，验证体系取代了外壳（harness）——当模型自己做正确的事，prompt注入保护、命令校验、权限模式等安全机制都不再重要，验证体系本身就是全部的"安全层"。([[boris-chenyi-sequoia-ai-ascent]])
- [[agent-immune-system]]：免疫系统是验证体系的"认知层"——不验证输出是否正确，而是验证输入是否安全。两者形成上下游互补
- [[recursive-self-improvement]]：递归自改进让验证体系面临极限测试——信任流程而非制品，但当流程本身也是AI的制品时，验证的根基动摇了。99.9%准确率在500代后衰减到60.5%（[[jack-clark-ai-self-construction]]）
- [[workflow-over-prose]]：验证退出标准是"流程"区别于"散文"的关键属性——没有退出标准的"最佳实践"只是散文，agent读完跳过；有退出标准的工作流才能被验证 ([[addyosmani-agent-skills]])
- [[anthropic-harness-design]] — Anthropic三Agent架构中Evaluator用Playwright MCP点进页面做QA，是Agent输出验证从"审查代码"到"验证可观测行为"的精确实现——不看代码，看运行结果。Sprint Contract在写代码前协商"done"的定义，是验证体系的上游约束
- [[openai-harness-engineering]] — OpenAI百万行代码实践中"Agent审核Agent"：几乎所有审核工作从人工转向Agent-to-Agent，是验证体系从人类审查到Agent互审的规模化路径——验证的执行者从人变为Agent，验证的流程不变
- [[generator-evaluator-loop]] — Evaluator Agent是验证体系自动化的实现：独立Agent替代人工审查，把"人读人审"推进到"Agent审Agent"。Sprint Contract的"done"定义等价于验证退出标准的Agent间协商
- [[agent-harness-anatomy]] — 验证循环是Akshay划分的12组件之一，Boris Cherny指出让模型验证自己工作可提升2-3倍产出质量——这是区分"玩具演示"和"生产级Agent"的关键
