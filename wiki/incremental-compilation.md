# 增量编译

在知识编译工作流中，只处理新增或变更的原始素材，而非每次全量重建整个知识库的优化机制，类似软件工程中的增量构建。

## TL;DR

首次编译可能需要30-60分钟，后续增量编译只需几分钟，通过智能依赖分析和变更传播，保持知识库的一致性和新鲜度，同时大幅降低计算成本。

## 问题背景

### 全量编译的挑战
- **计算成本高**：每次重新处理所有原始素材，浪费资源
- **响应速度慢**：添加几篇新文章需要等待完整编译完成
- **用户体验差**：无法快速看到新内容的效果
- **规模不可扩展**：知识库越大，全量编译时间越长

### 实际需求
- **频繁更新**：每日新增几篇网页文章、播客笔记
- **局部变更**：大多数时候只涉及部分内容的更新
- **即时反馈**：希望添加新素材后能快速看到编译结果
- **资源效率**：个人设备计算资源有限，需要高效利用

## 增量编译机制

### 触发条件
- **文件系统监控**：检测`raw/`目录中新增或修改的文件
- **手动触发**：用户显式请求编译特定内容
- **定时触发**：每日固定时间自动处理积累的新素材
- **阈值触发**：积累5-10篇新素材后自动触发

### 变更检测
1. **文件哈希对比**：计算文件哈希值，检测内容变更
2. **元数据对比**：比较作者、发布日期、来源URL等元数据
3. **依赖分析**：分析变更内容可能影响的相关概念
4. **影响范围评估**：确定需要重新编译的范围

### 编译优化
- **只处理变更文件**：跳过未变更的原始素材
- **依赖传播**：变更内容可能影响的相关概念页也更新
- **并行处理**：多个独立变更可并行编译
- **缓存利用**：复用之前的编译结果，只计算差异

## 工作流设计

### 首次编译（全量）
```
所有raw文件 → LLM编译 → 完整wiki结构建立
```
- **建立基线**：创建完整的知识网络
- **计算依赖**：分析概念间的关联关系
- **生成索引**：建立全局索引和主题地图
- **时间成本**：30-60分钟（取决于原始素材量）

### 增量编译（日常）
```
新增/变更raw文件 → 依赖分析 → 局部编译 → wiki更新
```
- **变更识别**：识别具体哪些内容发生了变化
- **影响评估**：确定需要更新的wiki页面范围
- **局部重建**：只重新编译受影响的部分
- **链接更新**：更新相关页面的交叉引用
- **时间成本**：几分钟（通常2-5分钟）

### 定期全量编译（维护）
```
每周/每月 → 全量检查 → 优化重构
```
- **健康检查**：全量一致性、完整性检查
- **结构优化**：重新组织知识网络结构
- **性能优化**：优化索引和检索效率
- **质量保证**：确保长期运行后的知识库质量

## 技术实现

### 依赖关系管理
- **概念依赖图**：记录概念间的引用关系
- **源文件-概念映射**：跟踪每个概念来自哪些源文件
- **变更传播算法**：当源文件变更时，自动更新相关概念
- **冲突检测**：检测变更可能引起的定义冲突

### 缓存策略
- **编译结果缓存**：缓存每个源文件的编译结果
- **中间表示缓存**：缓存LLM处理中的中间表示
- **索引缓存**：缓存索引计算结果
- **智能失效**：当依赖变更时自动使相关缓存失效

### 一致性保证
- **原子更新**：编译要么完全成功，要么完全回滚
- **版本管理**：每次编译生成版本标签，支持回退
- **并发控制**：防止同时编译导致的不一致
- **完整性检查**：编译后自动运行基础检查

## 效率对比

### 编译时间对比
| 知识库规模 | 全量编译时间 | 增量编译时间 | 效率提升 |
|---|---|---|---|
| 小（<50篇） | 10-20分钟 | 1-2分钟 | 10倍 |
| 中（50-200篇） | 30-60分钟 | 2-5分钟 | 12-30倍 |
| 大（>200篇） | 2-4小时 | 5-10分钟 | 24-48倍 |

### 资源使用对比
- **计算资源**：增量编译减少80-95%的LLM token消耗
- **内存使用**：只加载相关上下文，大幅降低内存需求
- **磁盘I/O**：只读写变更相关文件，减少I/O压力
- **网络请求**：减少外部API调用次数和成本

## 与软件工程类比

| 软件工程 | 知识库工程 |
|---|---|
| 增量构建 | 增量编译 |
| Makefile依赖管理 | 概念依赖图 |
| 编译器缓存 | 编译结果缓存 |
| 持续集成 | 定期健康检查 |
| 热重载 | 实时知识更新 |

## 实践优势

### 用户体验
- **快速反馈**：添加新素材后几分钟内看到结果
- **低延迟**：不影响日常查询和使用
- **可预测性**：编译时间稳定可控
- **透明性**：清楚知道编译进度和影响范围

### 系统效率
- **资源节约**：大幅降低计算成本和等待时间
- **规模扩展**：支持知识库规模自然增长
- **可用性**：编译过程不影响知识库查询功能
- **维护性**：简化日常维护工作

### 质量保证
- **一致性维护**：确保变更正确传播到相关概念
- **错误隔离**：局部问题不影响整个知识库
- **追溯能力**：清楚知道每个概念的来源和变更历史
- **恢复能力**：支持版本回退和错误修复

## 实施建议

### 初始设置
1. **建立依赖跟踪**：首次编译时记录完整依赖关系
2. **配置监控**：设置文件系统监控或手动触发机制
3. **定义变更策略**：明确什么程度的变更触发增量编译

### 日常使用
1. **批量处理**：积累一定数量新素材后一次性处理
2. **优先级管理**：重要内容优先编译，次要内容批量处理
3. **质量检查**：增量编译后运行快速健康检查

### 优化调整
1. **性能监控**：跟踪编译时间和资源使用
2. **规则调优**：根据实际使用情况优化触发条件
3. **缓存优化**：调整缓存策略提高命中率
