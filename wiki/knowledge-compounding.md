# 知识复利

知识管理中的复利效应：每次查询和交互产生的有价值结果被保存回知识库，使知识基础随时间呈指数增长。

## 机制

```
提问 → 综合回答 → 写回wiki → 知识库增值 → 更好回答基础
```

## 具体表现

1. **查询结果资产化**：有价值的分析、比较、洞察成为新的wiki页面
2. **上下文累积**：每次交互都增加知识库的深度和广度
3. **网络效应**：新页面与现有页面互链，提升整体价值
4. **正反馈循环**：更好的知识库→更好的回答→更多知识添加

## 实例：GPU租赁与漫剧成本分析

来自[[karpathy-llm-knowledge-management]]的案例：
- **初始状态**：wiki有GPU价格数据、漫剧行业报告
- **提问**："GPU租赁价格还在涨吗？对AI漫剧生产成本有什么影响？"
- **分析过程**：结合wiki数据+外部搜索验证
- **反直觉发现**：GPU涨40%，但漫剧成本从2000-5000→400元/分钟
- **原因**：头部团队自建算力+开源模型+工具链自动化
- **成果**：新页面《[[漫剧工具推理经济学]]》被创建并链接回相关概念

## 与传统问答对比

| 传统问答 | 知识复利模式 |
|---|---|
| 回答消失在聊天历史 | 回答成为永久知识资产 |
| 每次重新发现 | 基于累积上下文 |
| 零和游戏 | 正和游戏 |
| 知识不增长 | 知识指数增长 |

## 实现条件

1. **结构化知识库**：wiki提供可扩展的存储框架
2. **自动链接维护**：LLM处理新页面的交叉引用
3. **价值判断**：识别哪些回答值得保存
4. **集成工作流**：从查询到保存的无缝流程

## 复利曲线

- **早期**：线性增长，建立基础框架
- **中期**：加速增长，网络效应显现
- **长期**：指数增长，知识深度和关联度大幅提升

## 实践意义

将LLM从"一次性答案生成器"转变为"知识共同建设者"，特别适合：
- 长期研究项目
- 专业知识领域建设
- 团队知识积累
- 个人学习轨迹追踪
