# 知识库健康检查

将软件工程的Lint/CI/CD理念应用于知识库维护的系统化方法，通过定期自动检查确保知识库的一致性、完整性和网络健康度。

## TL;DR

每周自动执行三项检查（一致性、完整性、孤岛），生成健康报告并给出修复建议，让搜到一条笔记时敢直接使用，无需担心"这玩意靠谱吗"。

## 问题背景

### 知识库的"技术债"
- **定义冲突**：同一概念在不同地方定义不一致（如"RAG"在一个地方叫"检索增强生成"，另一个地方变成"向量数据库搜索"）
- **缺失内容**：概念条目缺定义、缺例子、缺来源
- **信息孤岛**：笔记入链/出链不足，难以被发现和关联
- **过时信息**：未及时更新或补充新证据

### 传统维护困境
- **手动检查不可持续**：靠人定期整理笔记库，理论上可以，实际上不可能持续
- **问题累积**：时间越长越乱，直到搜到矛盾结论搞不清哪个是对的
- **信任危机**：不敢直接使用搜索结果，需要额外验证

## 健康检查系统设计

### 检查频率：每周自动执行

### 1. 一致性检查
- **定义一致性**：同一概念在不同页面定义是否一致
- **术语一致性**：相同术语是否指向相同含义
- **引用一致性**：交叉引用是否正确、完整
- **冲突检测**：自动识别定义冲突，提示人工审查

### 2. 完整性检查
- **字段完整性**：概念条目是否包含必要字段（定义、例子、来源、相关概念）
- **证据完整性**：结论是否有足够证据支持
- **来源追溯**：每个声明是否能追溯到原始来源
- **孤证警告**：单一来源的结论需要特别标注

### 3. 孤岛检查
- **入链分析**：哪些笔记入链少于2？（没有足够页面引用它）
- **出链分析**：哪些笔记出链少于2？（没有足够链接到其他页面）
- **网络密度**：知识网络整体连接度
- **修复建议**：自动推荐应建立的链接关系

## 健康报告输出

### 报告位置
```
outputs/health/YYYY-MM-DD.md
```

### 报告内容
1. **问题清单**：分类列出发现的所有问题
2. **修复建议**：针对每个问题的具体修复方案
3. **健康度评分**：整体知识库健康度评分（0-100）
4. **趋势分析**：与上周/上月对比，健康度变化趋势
5. **优先级排序**：按严重程度和修复难度排序

### 报告价值
- **可操作反馈**：不只是发现问题，还给出修复方案
- **信任建立**：搜到一条笔记时敢直接使用
- **质量保证**：持续维护知识库质量，防止"技术债"累积
- **进度追踪**：可视化知识库改善进度

## 实现机制

### 检查工具
### LLM驱动检查
- **批量分析**：LLM读取所有相关页面，进行一致性分析
- **语义理解**：理解概念本质而非简单字符串匹配
- **上下文感知**：考虑概念在不同上下文中的合理变化

### 脚本自动化
- **定期触发**：每周自动运行健康检查脚本
- **增量检查**：只检查新增/变更内容，提高效率
- **结果归档**：自动保存历史报告供趋势分析

### 与编译工作流集成
- **编译时检查**：在编译新内容时同步进行基础检查
- **修复自动化**：简单问题（如缺失链接）可自动修复
- **人工审查**：复杂问题（定义冲突）需要人工决策

## 检查示例

### 一致性冲突示例
```
问题：概念"RAG"定义不一致
页面A：检索增强生成（Retrieval Augmented Generation）
页面B：向量数据库搜索（Vector Database Search）
建议：统一使用"检索增强生成"，或明确区分两种含义
```

### 完整性缺失示例
```
问题：概念"知识复利"缺少关键字段
缺失：实际案例、量化效果、适用场景
建议：补充[[karpathy-obsidian-rebuild]]中的一小时改造案例
```

### 孤岛检测示例
```
问题：页面"AI漫剧经济学"链接不足
入链：1个（来自推理成本）
出链：0个
建议：链接到GPU租赁、开源模型、工具链自动化
```

## 实践效果

### 质量提升
- **定义清晰**：概念定义一致、明确
- **证据充分**：每个结论有足够来源支持
- **网络健全**：知识节点充分互链，易于发现和导航

### 维护效率
- **早期发现**：问题在积累前就被发现和修复
- **自动化修复**：30-40%的问题可自动修复
- **预防为主**：通过检查规则预防新问题产生

### 用户信任
- **搜索结果可信**：敢直接使用搜索到的内容
- **知识复用**：放心引用wiki中的概念和结论
- **协作基础**：团队共享知识库时减少沟通成本

## 实施建议

### 启动阶段
1. **首次全面检查**：对现有知识库进行全面基线检查
2. **建立检查规则**：定义什么算问题、什么程度需要修复
3. **设置优先级**：先解决严重问题，再优化细节

### 运行阶段
1. **每周例行检查**：建立固定检查节奏
2. **增量优化**：每次解决一批问题，持续改进
3. **规则迭代**：根据检查结果优化检查规则

### 成熟阶段
1. **预防性规则**：在编译阶段阻止常见问题
2. **自动化修复**：提高自动修复比例
3. **质量指标**：建立知识库质量量化指标体系
