# 几乎没人答对一个问题：AI 产品经理到底应该干什么？

Cat Wu 是 Anthropic Claude Code 和 Cowork 的产品负责人。面试几百个 PM 后，她的核心发现是：**大多数人对 AI PM 角色的理解方向不对**——他们还活在 6-12 个月路线图的旧世界。

## TL;DR

AI 时代 PM 的核心工作不是跨团队路线图对齐，而是缩短"有想法→到用户手里"的时间。Anthropic 把交付周期从半年压到一天，靠的不是更强的模型，而是流程和团队文化。

## 与 Boris 的搭档

Cat 和 Boris Cherny（Claude Code 技术负责人）的关系是 **"80% mind-meld"**：Boris 定方向（3-6 个月后产品应该长什么样），Cat 把愿景翻译成执行路径 + 做跨职能协调。剩下 20% 各自推自己在意的事，**谁更在意谁就推**。

## AI PM 的三大新职责

1. **设定清晰目标** — LLM 能力太通用，用户和场景都模糊，PM 必须把核心用户、核心场景、目标定死
2. **[[research-preview|Research Preview 机制]]** — 以研究预览形式发布，明确告知早期状态，降低发布门槛
3. **搭建发布流水线** — "evergreen launch room"机制：工程师觉得功能准备好了就发到频道，文档/营销/DevRel 第二天完成对外宣传

> 搭建这套发布流水线，就是 PM 该干的事。

## PRD 的替代方案

PRD 没死但活法不同了：**每周 metrics readout** + **team principles**（核心用户、为什么、做什么取舍）替代了大部分 PRD。只有特别模糊或需要大量基础设施投入的项目才有一页纸 PRD。

## [[role-convergence|角色融合]]

**所有角色都在融合**：PM 写代码，工程师做产品决策，设计师做 PM 的活也提交代码。Anthropic 选择大量招有产品品味的工程师，而不是多招 PM 来引导。团队里几乎所有 PM 有工程背景或直接写代码，设计师都做过前端工程师。

> 当代码变得越来越便宜，真正变得更有价值的是决定写什么。

## [[agi-pilled|恰好正确程度的 AGI 信仰]]

全场最有洞察力的观点：**最难的是定义产品一个月后应该长什么样**。太 AGI pilled 会忽略眼前痛点，太保守会在模型升级时措手不及。最好的 PM 能看到用户如何突破现有产品极限，从中判断方向。

Cat 自己花 30% 的时间故意把 Cowork 推到极限，和模型对话搞清楚它为什么犯错。

## 速度的代价

最大代价是 **产品一致性**。有时同时推出功能重叠的东西，让用户告诉他们哪个更好。代价是新用户不知道最佳路径。

## 源代码泄露

Claude Code 源代码通过 npm 包泄露，经过两层人工审查仍漏过。Cat 定性为 **流程失败**，相关人员未被开除——"最重要的是学习教训、加强防护"。

## OpenClaw 封堵

Cat 从容量管理角度解释：订阅计划不是为第三方产品的使用模式设计的。但时间线上的巧合（Cowork 推出类似功能后封堵第三方订阅通道）仍是社区争议核心。

## 产品愿景：[[agent-matrix|从单任务到 Agent 矩阵]]

核心构建单元是单任务成功率。随模型变强，用户从单任务→多任务并行→同时跑 50-100 个 Claude。**路线从单兵作战走向 Agent 矩阵。**

## Anthropic 为什么能赢

**统一使命**：团队愿意牺牲自己的 KR 去服务公司整体目标。使命高于任何单个产品线，跨组织决策快，执行统一。

## Claude 的性格是护城河

两个核心特点：**低 ego**（做错了不辩解，马上修）+ **积极正面**（面对无从下手的任务，主动提议"我先帮你动手"）。目标是做那种"能量特别好"的同事。

## 编辑手记：三个矛盾

1. **速度文化 vs 安全承诺** — 一周两次信息外泄，对速度文化本身是否加剧风险没有反思
2. **开放生态 vs 围墙花园** — OpenClaw 封堵时间线与 Cowork 功能扩展的巧合
3. **PM 价值悖论** — 最高效模式是"工程师端到端不需要 PM"，但 PM 的价值答案是 product taste——这个概念停留在抽象层面，没有可操作的定义
