# TCP 为什么是三次握手，而不是两次或四次？

## TL;DR

三次握手不是经验参数、不是历史遗留——它是不可靠信道上建立双向可靠通信的信息论下界。少一次信息不足，多一次徒增成本，三次是刀锋上的平衡点。

## 核心论证链

文章从六个独立维度收敛到同一个数字3：

| 维度 | 为什么是三次 |
|---|---|
| 信息论 | 两个实体交换并确认两个独立随机数（ISN），至少需要3次报文 |
| 状态机 | 双方各需SYN和ACK，同方向可合并，2×2-1=3 |
| 可靠性 | 超过3次的纯确认不增加可靠性（[[two-generals-problem|两将军问题]]） |
| 效率 | 3次是满足约束的最小RTT开销 |
| 安全 | 第3次报文为被动方提供验证主动方存活性的关卡 |
| 历史报文 | 第3次报文使被动方能识别并拒绝过期的SYN |

## 两次为什么不够

站在A视角，两次握手后A的四能力（发/收/B发/B收）全部确认。但B是瞎的——B不知道自己能不能发、不知道A能不能收。信息不对称未消除。

工程后果：SYN Flood攻击。两次握手下B收到SYN就分配资源，伪造SYN涌来即耗尽内存。

## 四次为什么多余

四次握手的第2步（B→A: ACK）和第3步（B→A: SYN）方向相同、发送者相同，合并为SYN+ACK即三次。奥卡姆剃刀：效果相同选简单的。

**为什么挥手是四次？** 断开是非对称的——A说"我不发了"（FIN），B说"知道了"（ACK），但B可能还有数据没发完，ACK和FIN之间存在时间差，无法合并。

## 两将军问题的幽灵

[[two-generals-problem|两将军问题]]已证明：不可靠信道上不可能达成100%确定共识。三次握手不追求消灭不确定性，而是压缩到可容忍程度后用超时重传兜底。超过3次的纯确认不增加可靠性——每多一轮确认，新的不确定性恰好抵消确定性增益。

## 资源分配的时机

三次握手给了B一个验证对方存活性的窗口：只有能正确回复ACK的A才值得B分配资源。SYN Cookie技术利用这个窗口，在第3次握手前不分配状态。
