# 三次握手

## TL;DR

三次握手不是经验参数，是不可靠信道上建立双向可靠通信的信息论下界。少一次信息不足，多一次徒增成本。

## 什么是"握"的

TCP连接是全双工的，握手本质是确认四个命题：A能发、A能收、B能发、B能收。但更本质的框架是ISN共识——双方不仅要互相知道对方的初始序列号，还要确信对方知道了自己知道了。这是分布式系统中身份互信的信息论下界。

```
第1次 A→B  C_A         B获知C_A
第2次 B→A  C_B+"已知C_A"  A获知C_B；A确认B已知C_A
第3次 A→B  "已知C_B"      B确认A已知C_B
```

三次之后，信息对称性完全消除。

## 日常类比

两个人打电话确认约会：

```
A: "明天三点见？"          ← 第1次：A发出提议
B: "好，明天三点。你听到了吗？"  ← 第2次：B确认+反问
A: "听到了。"              ← 第3次：A确认B的确认
```

两次不够：B问了"你听到了吗"但没得到回答，B不敢确定A到底来不来。四次多余：A不需要再问"你确认我听到了吗"，因为A已经回答了，再多一轮只是原地打转。

这和TCP三次握手是同一个结构：双方需要达成双向共识，三次是信息对称性消除的最小步数。

## 两次不够

B发出第2次报文后，不知道自己能不能发（没人确认报文到达），不知道A能不能收。信息不对称未消除。工程后果：SYN Flood——伪造SYN涌入即耗尽被动方资源，因为两次握手下被动方没有验证窗口。

## 四次多余

四次的第2步（ACK）和第3步（SYN）方向相同、发送者相同，合并为SYN+ACK即三次。奥卡姆剃刀：效果相同选简单的。

**为什么挥手是四次？** 握手是对称的（双方都没有历史数据），挥手是不对称的（被动方可能还有数据在途，ACK和FIN之间存在时间差，无法合并）。

## 与两将军问题的关系

[[two-generals-problem|两将军问题]]证明：不可靠信道上不可能达成100%确定共识。三次握手不追求消灭不确定性，而是压缩到可容忍程度后用超时重传兜底。超过3次的纯确认不增加可靠性——每多一轮，新的不确定性恰好抵消确定性增益。

这是[[bounded-rationality|有限理性]]在协议层的实例：不追求完美共识，追求"足够好"的共识。三次是"足够好"的最小代价。

## 与理解作为云的形状

用[[understanding-as-cloud|李继刚的理解模型]]看，课本给的是点（SYN→SYN+ACK→ACK），这篇文章长的是云。纵向爬了五层：

```
最远  信息论下界：不可靠信道上双向共识的最小交换次数
  ↑   两将军问题：完美共识不可达，"足够好"可以
  ↑   ISN同步：A知道C_B ∧ B知道C_A ∧ 双方确信对方已知
  ↑   四能力确认：A发/A收/B发/B收，缺一不可
贴脸  报文序列：SYN → SYN+ACK → ACK
```

能从顶层滑回底层且每层站住，是费曼第一刀通过的标志。
