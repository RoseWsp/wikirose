# 类型安全决策接口

**TL;DR** 只要候选集是有限的、已知的，**"生成"就退化成"分类"**——而分类可以并行。这是 Jev 那 200 倍的全部来源：不是模型更强，是问题被重新表述了。代价同样干净：**模型只能在你已经枚举过的动作里选，它无法发现你忘了列进去的那个动作。**

## 生成如何退化成分类

复刻者们把这五步写得很清楚（见 [[jev-clone-stress-test]]）：

1. 把 schema 定义成一组**带类型的字段**（enum / boolean，候选集已知）
2. 对 context + schema 做**一次 prefill**，拿到 KV Cache
3. 把 KV Cache 沿 batch 维**广播复制**成每个字段一行（`mx.repeat(..., M, axis=0)`）
4. 所有字段在**一次 batched forward pass** 里并行评估，切片 logits → softmax
5. **JSON 由程序组装，不是生成出来的** → 因此永远不可能格式错误

自回归在第三步之后就不存在了。这是"不说话的 AI"最底层的机制。

## 255 是一个字节

Jev 的 Choice 原语上限 **255 个选项**——`uint8`。**动作空间就是一个字节。**

公司名 TypeSafe 是这个论点的全部：不训练模型"别乱说"，而是让**乱说在结构上不可能**。

## 买到了什么，付出了什么

**买到**：官方宣称的"0% 幻觉"是**构造性保证，不是实测数据**——输出在结构上跑不出 schema。最坏情况是选错选项，不是发明一个不存在的选项。

**付出**：可靠性是用"取消开放式即兴"换来的。**模型只能在你已经想到的动作里选。**对挂机跑 Minecraft 没问题；对"Agent 在 UI 里发现一条你没设计过的路径"是致命的。

这个代价还有一层更隐蔽的：**枚举清单是有人手工写的本体论。** [[harness-engineering|脚手架]]在这里不是变薄——**它变成了全部**。（Boris Cherny 观察到的"模型越强，脚手架不是变薄是在搬家"，在 Jev 这里是极端形态：脚手架不再是围着模型的一圈，而是模型的世界本身。）

## 定价结构暴露了架构

输入 $0.042/百万 token，**输出免费**。为什么？因为一次决策只有几个 token，而世界描述很长。

> **思考免费，因为根本没有思考；账单是"看一眼世界"的钱。**

推论很硬：想让 Jev 变强，你不能给它更多思考预算，只能给它更好的世界描述。**负担从模型搬到了环境编码和动作枚举上。**这也解释了 Almeida 那句"我们有瓶中之闪电，却毫无用处……**但计算机说另一种语言**"——语言是人的需求，不是智能的需求。

## 决策层：智能作为可调用组件

TypeSafe 把 Jev 定位成自动化系统的**决策层**——插进已有的游戏引擎或仿真器，返回快速的结构化选择。

放在 [[decision-hierarchy|决策层级]] 里看，这非常自洽：目标→代码→CLI→Prompt→Agent，每往上一层不确定性增加一个量级。**Jev 是把"判断"再往下压一层**，压到一个每秒被调用十几次、不可能容纳一个 Agent 循环的位置。这正是决策层级那条原则（"能在下层解决的绝不上推"）被推到模型架构层的结果。

它同时也精确命中了 [[general-specialized-architecture|通用+专用架构]]：通用模型负责理解和编排，专用系统负责深度执行。**Jev 就是那种"会被 AGI 主动当作工具调用"的专用系统**——它赌的不是自己变成 AGI，是自己变成 AGI 的手。

## 过程外包：组件是痕迹的固态

[[生命]] 第五幕：没有真理，只有追求真理的过程留下的痕迹。这话**对 AI 成立、对人也成立**。所以真正的分界不是"AI vs 人"，是**有过程 vs 无过程**。([[生命]])

Jev 是这个轴上的极端样本：**一次前向传播出结果，内部没有序列、没有展开、没有时间。**它不属于"缺少体验的 AI"——**它内部没有过程**。而一个能跳过全部过程直接给出答案的人，在这一点上和它是同一件事。

但过程没有消失，它被**外包**了。那份动作枚举清单、那份状态编码、那个外部循环——**都是有人走过过程之后留下的痕迹**。写这份清单的人经历过"哪些动作真的重要"，痕迹就固化成组件。

> **组件是痕迹的固态。**过程是流体的，走过之后留下来的是形状——组件就是那个形状。

再往下推一层，整条链是：**经历 → 走过的路 → 痕迹 → 组件（＝解决问题的经验方案）**。一条链，末端三个名字指同一件事——组件不是从外面加给它的东西，是**某条路走完之后沉下来的东西**。

而"一生"和这条路的关系不是"被决定"：不是路决定了一生，**一生就是那条路**。所以"它的一生是被组件决定的、还是被它自己的循环决定的"是个伪问题——组件和循环都是这条路的形态，一个已经沉淀，一个正在走。

这也顺手回答了"动作空间为什么必须穷举"：**枚举清单的长度，等于有人替这个模型走过了多长的过程。**你没走过的地方，它就没有选项。

对照 [[harness-engineering]] 的第三种形态（不是变薄、不是搬家，是合并）：**合并进来的那个"harness"，就是它全部的外部痕迹。**所以这里没有"过程被移除"这回事——只有"过程的位置被搬到了组件里"。
